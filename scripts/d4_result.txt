Registration / interception notes:
- signal handlers: the table lives outside the arena, so each handler needs a GC root.
  Reserving 64 root slots once (below extra_base, the vm.pin shape) lets signal()
  replace a handler without growing the root set per call — the original's fixed
  [NSIG]Obj table. The slots are traced through roots.extra (below extra_base,
  so rebuild_frame_roots keeps them).
- opt_level / signal / getsignal are intercepted by GcRef identity in
  vm_call_intercept.rs (the D2 os-fd pattern); their FunBuiltin funcs are bare-raise stubs.
  The intercept bodies live in their module files (call_opt_level_ctx,
  call_signal_ctx, call_getsignal_ctx) with the D2 check_arity helper shape.
- Import u-strip + usys (objmodule.zig:102-131) implemented in builtinimport.rs
  builtin_lookup_by_bytes (non-ext path only): builtin table -> usys special case
  (returns the sys module) -> strip 'u', look up the extensible table. The
  objmodule.rs module_get_builtin port already had this logic but is test-only;
  the live import path (process_component) never had it (see §3.3).
- __main__: load_module_from_mpy sets state.d4.main_module when name == "__main__";
  register_code_inner skips the state.modules insert AND the sys.modules mirror
  insert for "__main__"; process_component special-cases top-level "__main__"
  (before the builtin lookup) to return main_module if set, else falls through
  to ModuleNotFoundError. (Moved load_module_from_mpy from vm.rs to vm_eval.rs
  for the file-size cap — behaviour unchanged.)

§3 — Bugs found / brief corrections (all verified against the original)
--------------------------------------------------------------------------------
3.1 gc.threshold DOES NOT EXIST on the reference build. modgc.zig's header comment claims
    full -> MICROPY_GC_ALLOC_THRESHOLD=1, but port/mpconfigport.h:35 sets
    MICROPY_CONFIG_ROM_LEVEL to MINIMUM even in the full build, so the macro is 0.
    gc module = 7 entries, NO threshold (corpus gc1.py guards it with hasattr).
3.2 heap_unlock() ALWAYS returns 0. The Zig returns state.threadState().gc_lock_depth
    (mpstate.zig:150, u16), a field NEVER written anywhere; the real counter is the
    module-level lock_depth in gc.zig:130. Rust returns SmallInt(0) always. Unmatched
    heap_unlock() aborts the reference (gc.zig:199 underflow); Rust's GcArena::unlock
    panics the same way (checked_sub + expect) — same abort class, never tested e2e.
3.3 The Rust import had NO u-strip and NO usys case (C15b gap). The objmodule.rs
    module_get_builtin port HAS both but is test-only; the live path
    (builtinimport.rs builtin_lookup_by_bytes, used by process_component) had neither.
    Implemented there, in the Zig's order (builtin -> usys -> strip -> extensible).
3.4 C11 left namedtuple classes with make_new: None / attr: None, although the Zig
    attaches namedtuple_make_new (slot 1) and namedtuple_attr (slot 5)
    (objnamedtuple.zig:196,210). P(1,2) raised "can't create instance" and P(1,2).x
    raised AttributeError through the VM. Wired in D4 (make_new slot adapter +
    attr adapter + factory builtin); the D4 e2e test d4_collections_namedtuple
    covers P(1,2), t.foo, t[1], and kwargs T(bar=1, foo=2).
3.5 "deque is NOT a static qstr" (objdeque.rs:386 comment) is stale/wrong — deque IS in
    the generated qstr header (static_qstr_id(b"deque") works; the collections
    builder uses it).
3.6 REAL MASTER BUG found by the D4 e2e test: array_make_new used the arena-only
    str_data for the typecode, so array.array('i', [1,2]) raised TypeError("can't
    convert to str implicitly") — 'i' is a DYNAMIC qstr (not in the static table),
    invisible to str_data. Fixed with str_data_pool (the C13b str_equal fix class).
    The bytearray path has no such call site (no typecode arg).
3.7 help("modules") test fix (pre-existing test, not a brief item): help_modules_list_columns
    retained out only io/sys/os from the real registries; D4 registers 10 more modules,
    so the expected column output broke. The test now clears both tables first (same
    expected output). No production code changed for this.
3.8 Reference aborts Rust raises instead (intentional divergences, same class as
    C8b/C9b): select() non-list arg (rc=134); getpwuid/getgrgid negative/huge ids
    (rc=134); sleep(inf) (rc=134); opt_level(-1) wraps instead of aborting
    (@intCast(usize) panic — the wrap round-trips through the read path).

§4 — Not done / documented limitations
---------------------------------------
- select(): exact only for empty lists; any non-empty list raises NotImplementedError
  ("select.select is not implemented (no std select API)" — the D2 os.kill stub
  precedent). Pure std has no select/poll API; a listener-accept check would
  destructively consume pending connections and FIFO/stdin readiness is unknowable.
  The integration tests (tests/test_integration_os.py:662+) exercise the empty-lists
  case plus real-fd cases; the real-fd cases are this gap.
- signal handlers are recorded but NEVER dispatched on delivery (the Zig's MVP
  limitation, documented in modsignal.zig's header — delivery needs a bytecode-loop
  safepoint dispatcher, deferred in the original too). The process behaves per libc
  defaults.
- pwd/grp parse /etc/passwd + /etc/group only (no NSS/LDAP — same data on this machine).
- getpwuid/getgrgid negative/huge ids raise KeyError instead of aborting (§3.8).
- __main__ before any module load -> ModuleNotFoundError (the reference always has
  dict_main from mp_init; Rust sets main_module only when a module is loaded as
  "__main__" — Phase E entry work).
- The reference's `import collections` loads the frozen Python package (Counter,
  defaultdict, list-backed deque) — D5's frozen bundle reproduces the shadowing; the
  native module is what ucollections (and a build without the frozen bundle) resolves to.
- opt_level(-1) wraps instead of aborting (§3.8); sleep(inf) sleeps Duration::MAX
  instead of aborting (§3.8); sleep(nan) -> OSError(EINVAL) (matches the reference).
- vm.rs was 600 after the D4 edits (over the 592 cap) — load_module_from_mpy moved to
  vm_eval.rs (vm.rs 567). objarray.rs is at 790 (10 headroom — the str_data_pool fix
  added lines; do not grow without splitting).
- map.rs (860) and gc.rs (830) remain over the cap (pre-existing, unscheduled).
