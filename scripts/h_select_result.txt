# H-select 结果（lane/h-select，基线 d316394）

## §1 改了什么

目标：`select.select` 按 Python API 统一行为、纯 Rust std、双构建一致；
默认构建 integration 200/202 → 202/202（`select_readable_fd_is_ready`、
`select_timeout_zero_returns_promptly` 两红变绿）。

### 新文件

- `src/support/readiness.rs`（新增，~620 行）：每 fd 一个 monitor 线程 +
  共享读缓冲。`ensure_monitor(fd, file)`（`File::try_clone`，共享
  description/offset）；`take_buffered` / `wait_buffered` /
  `drain_into(fd, buf) -> (usize, bool)`（两条读路径共用）；`note_closed`
  （标记 stale + 清缓冲，防 fd 号复用继承旧字节）/ `note_seek`
  （seek 后缓冲失效）；`wait_settled`（新 monitor 首读有界 10ms 握手，
  见下）；`reusable()` + `(dev, ino)` identity（fd 号复用时死 monitor
  的缓冲只在同一 description 时复用）；`BUFFER_CAP` 64 KiB 背压。
  只有一个文件放 monitor 表（`SOCKETS` 不动）。
- `tests/h_select.rs`（新增，10 个二进制探针，NO cfg 门控，双构建都跑；
  精确 stdout 断言，所以双构建 diff 天然为空）：FIFO 有数据 / 无数据
  （writer 全程持有）/ timeout=None；accepted socket 有数据仍 not-ready
  （pinned limitation，后续 recv 证明数据在）/ 无数据 not-ready；坏 fd -1
  与坏 wlist/xlist → OSError 9；`/dev/null` 文件对象 identity（`r[0] is f`）；
  fd ≥ 1024 接受且就绪；devnull + listener sanity。所有等待都有 deadline
  （子进程 15s、writer open / connect 5s，超时 kill）。

### 改写：`src/modules/modselect.rs`（367 行 → ~470 行，FFI 路径全删）

- 删：`ffi` mod、`FdSet`、`select_real`、`timeval_from_secs`、
  `list_len`、全部 `#[cfg(feature = "unsafe-ffi")]` 分支。
- `select.select(r, w, x[, timeout])` 新逻辑（见模块头文档）：
  入口一次性解析（CPython 入口校验所有 fd）；解析：int/bool 即 fd
  本身（堆 int 只认 exact int——float 不认，`obj_get_int_maybe` 会走
  `__int__` 把 3.5 读成 3，CPython 的 select 拒绝非整数）、文件对象
  （自己的 `File`，Owned 才可 monitor）、socket 实例（`self_socket`
  形：4 个 small-int subobj，[0] 为 fd）、其他对象走 `fileno()` 方法；
  再无则 TypeError。裸 fd 号：0/1/2（stdio）与越界 → EBADF；
  socket fd 经 `modsocket::socket_probe`（见下）；否则必须在
  `state.os_fds`（取 clone 的 `File` 供 monitor），未知 → EBADF。
- 探针循环 2ms quantum：文件 fd 由 monitor 判定（缓冲非空 / EOF /
  monitor 已死——死表示下一次读是 OS 读，会 surface 错误或 seek 后的
  新数据，所以报 ready 是对的）；socket fd 永不 ready；wlist 恒 ready
  （已校验，纯 std 无写就绪探针——文档化的近似）；xlist 恒空（已校验）；
  三表全空时 sleep timeout 后返回三个空表（`select(0, NULL, NULL, NULL, tv)`
  行为）；`timeout=None`/无穷循环等；有限 timeout 是 deadline（超大值在
  ~95 年处饱和——`Duration::from_secs_f64` 会在溢出时 panic，旧代码在
  同处也会 panic）。
- 保留的旧行为（2026-11-18 在 reference 上探过）：负/NaN timeout →
  OSError(22)；非 list 参数 → TypeError（"select() argument must be a list"）；
  少于 3 个参数（或任何关键字）→ TypeError（"argument num/types mismatch"，
  拦截绕过了 call machinery 的 arity 检查，所以检查移到 `select_ctx` 里）；
  三个结果表是 DISTINCT 的表。
- 与 reference 的分歧（沿用旧版）：非 list 参数 reference 会 ABORT
  （`incorrect alignment` panic，rc=134），Rust 抛 TypeError；无穷 timeout
  reference 会 ABORT（`@intFromFloat` panic），Rust 永久循环。旧 feature
  路径的真 `select(2)`（FD_SETSIZE 1024 上限、fd < 0 / ≥ 1024 静默跳过）
  已删：Python 没有 fd 上限，未知 fd 现在是 EBADF 而不是静默跳过。旧默认
  路径的非空表 → NotImplementedError 已删——这就是本 lane 的目的。
- `FunBuiltin` 槽是 stub（直接调用时抛 NotImplementedError "select.select
  called without VM state"）；真正入口是 `call_select_ctx`（拦截用）；
  `build_select_module` 返回 `(module, select_fn)`（`build_gc_module` 形）。

### 接线（brief 文件清单之外，必需——见 §4(4)）

- `src/runtime/vm.rs`：`VmState.select_builtin: Value`（init `Value::None`）。
- `src/runtime/vm_modules.rs`：`build_select_module` 解构出 `select_fn`，
  存入 `state.select_builtin`。
- `src/runtime/vm_call_intercept.rs`：`fun == state.select_builtin` 时调
  `modselect::call_select_ctx`（os fd builtins 同形——`FunBuiltin` 槽看
  不到 `state.os_fds`）。
- `src/modules/modsocket.rs`（+39 行，唯一新增）：`socket_probe(fd) ->
  Option<SocketProbe>`（`Unprobable`：stream/listener/未绑定/他人所有；
  `Bare`：`fromfd` 且无自有对象 → EBADF，与已有“他人 fd 上 I/O”规则一致）。
  除此之外不碰 modsocket（H-socket 的文件）。

### 读路径（防数据丢失——select 启动 monitor 后，读必须先排空缓冲）

- `src/objects/containers/objfileio.rs`：`fileio_read` 先 `drain_into`，
  只有无活 monitor 时才读 OS 剩余部分（活 monitor + 空缓冲时 BLOCK，
  绝不返回 0——`stream_rw_loop` 会把 0 读成 EOF）；SEEK 成功 →
  `note_seek`；CLOSE → `note_closed`。
- `src/runtime/modos_fd.rs`：`os_read_ctx` 同样先排空（`os.read` 返回一次
  读到的量，排出的缓冲即算一次读）；`os_lseek_ctx` 成功 → `note_seek`；
  `os_close_ctx`（双臂）→ `note_closed`。
- `readiness::drain_into` 是两条读路径的共享实现（原先 objfileio 的私有
  `drain_buffered` 已删）。

### 关键修复（测试中发现的真 bug）

1. **首读竞态（settle 握手）**：新 monitor 的首次 read 还没发生时，
   timeout=0 的第一次 probe 已跑完，`/dev/null`（已 EOF）被误报 not-ready
   （lib 3 个测试失败）。修法：`ensure_monitor` 对新 monitor 做一次有界
   等待（`wait_settled`，`data` condvar + 10ms deadline——monitor 每次 read
   完成都会通知；空管道的阻塞 read 永不通知，deadline 到即返回，不会挂住）。
   只对新 monitor 等（复用的早已 settled），每 fd 只付一次（空管道首 select
   最多 10ms）。回归测试 `fresh_monitor_settled_on_eof`。
2. **fd 号复用挂住**：FIFO 测试的 O_RDWR monitor 靠自己的 dup 持有写端，
   read 永不回 EOF，monitor 活过测试；下一测试复用同一 fd 号时
   `ensure_monitor` 返回了残留的活 FIFO monitor。修法：`reusable()`——
   仅当非 stale、identity 匹配（双已知时）、且（活着 或 死而有字节）才复用；
   不可复用的标 stale 并替换；`note_closed` 同时清缓冲（已关闭 description
   的预读字节不可达，否则同文件重开会继承——`(dev, ino)` 分不出来）。
3. **feature `os.close` 双重 close（pre-existing G6a bug，本 lane 修）**：
   feature 分支先 `sys_close(fd)` 再 drop 表里的 `File`，fd 被关两次；
   debug 直接 abort（"IO Safety violation: owned file descriptor already
   closed"，rc=134；不经过 select 的 `os.open` + `os.close` 最小复现亦然），
   release 下第二次 close 可能落在复用的 fd 号上。G6a 注释以为重关的
   EBADF 会被忽略——debug 下不是。修法：`sys_close` 成功后用
   `into_raw_fd()`（safe，只转移所有权不关闭）消费掉表里的 `File`。
   `stdio` 分支不受影响（无 File 可 drop）。另见 §4(9)：`os.close(f.fileno())`
   （f 为 `open()` 文件对象）仍是同类隐患，未修。

## §4 遗留项

1. **Socket（stream/listener/未绑定）永不 ready**——`UnixStream::peek`
   仍是 unstable（stable rustc 1.99.1 上不可用），monitor `recv` 会消费
   socket `recv` 路径不排空的字节。解开办法：socket monitor + `recv`
   排空进 `modsocket.rs`，在 H-socket 重写落地后做（会碰 H-socket 的
   `recv` 路径）。后果：brief 里的 socket-pair 探针（accepted socket 有
   数据 → ready）无法通过，现作为 pinned-limitation 探针（assert
   not-ready + 注释）。Listener 同类：`accept` 会消费 pending 连接，
   故同样 not-ready；`g0_select_listener_readable_then_drained`（feature
   原先经真 `select(2)` 通过）已改为 assert 该 limitation。
2. **Brief 的 "clone 保护原 blocking 状态" 在 OS 层面是错的**——`O_NONBLOCK`
   是 per-description 的，dup 共享它（已有的 `setblocking` 行为亦然）。
   peek 取消后此点已无关，记于此。
3. **fd 0/1/2（stdio）→ EBADF**——std 里没有 stdio 的安全 `File`；
   `/proc/self/fd` 重开是 Linux-only，且对常规文件是错的（独立 offset）。
4. **brief 文件清单之外的改动**：`modos_fd.rs`（os.read/os.close/os.lseek
   接入 monitor）与 VmState/拦截接线是必需的——没有它们，`select([os_fd])`
   启动 monitor 后，后续 `os.read(fd)` 会跳过已缓冲的字节（数据丢失）；
   同理 `VmState.select_builtin` + 拦截（`FunBuiltin` 看不到 `os_fds` 与
   socket 表）。
5. **同文件重开的残留口子**：旧 monitor 还活着、且 `note_closed` 从未被调
   用时，同文件重开可能复用旧 monitor。所有 close 路径都已接线，所以这
   需要一次未接线的 close 才会发生。
6. **`__index__` 对象不接受**：只认 exact int 与 `fileno()`。CPython 的
   select 还接受带 `__index__` 的对象（无 `fileno()` 时）；petitpy 里
   `__index__` 罕见，未做。
7. **wlist 恒 ready、xlist 恒空是近似**：纯 std 没有写/异常就绪探针。
   对常规文件/管道写端恒 ready 是对的；对满的管道写端会误报（调用方
   write 会阻塞）。xlist 在 Linux 上几乎恒空，与 CPython 一致。
8. **`poll` 未做**：原项目没有 `poll`（brief 亦然）；可作后续。
9. **feature `os.close(f.fileno())`（f 为 `open()` 文件对象）仍双重 close**：
   `sys_close` 关掉 f 的 fd 后，f 的 `File` Drop 会再关一次（debug abort，
   release 可能关到复用的号）。与 §1 修复的同类问题，但涉及 `open()` 文件
   对象的关闭路径，未在本 lane 修（超出 select 范围；需让 File 对象释放
   所有权）。
10. **集成探针只放在 `tests/h_select.rs`**：brief 让往
    `tests/test_integration_os.py`（orig 仓库）的 select 节加探针，但 orig
    仓库只读；`tests/h_select.rs` 覆盖了同等场景。
11. **Settle 等待的代价**：空管道的首个 select 最多等 10ms（每 fd 一次，
    复用不付）。`select_timeout_zero_returns_promptly`（listener，0.2s
    量级）不受影响（socket 无 monitor）。
12. **Monitor 线程残留泄漏**（readiness.rs 模块文档已有）：fd 被从外部
    关闭后，阻塞在 `read` 里的 monitor 要等下一次 read 事件才退出；每
    个被丢弃的 description 最多一个阻塞线程。
13. **超大有限 timeout 在 ~95 年处饱和**（`Duration::from_secs_f64` 溢出
    panic，旧代码同处也会 panic；无穷 timeout 仍永久循环，与旧默认路径一致）。
