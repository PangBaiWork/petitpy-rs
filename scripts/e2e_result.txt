§3 — Fixes (each probed against the reference binary)
-----------------------------------------------------
Fix A — bytes/array/bytearray buffer operands (item 1).
Root cause: binary_op_inner (objstr_methods_c.rs) already
tried buffer_data(ctx, types, rhs) for a bytes lhs with a
different-type rhs — but buffer_data (objstr_a.rs) failed
for array/bytearray because get_buffer returns Ok(true)
with a raw pointer that can only be read with unsafe
("Unreachable today: str/bytes are the only buffer
providers"). The safe reader already existed:
buffer_bytes (containers/binary.rs:572) handles Obj::Array
(incl. view chains via source), Obj::Bytes, Obj::Str,
Qstr — returns (Vec<u8>, typecode). Fix: in buffer_data,
after str_data_pool returns None, try buffer_bytes and
return its bytes. This fixes Add/Contains/comparisons via
the str slot AND bytes(array)/bytes(bytearray) via
bytes_make_new (which calls buffer_data).
Vendor rules (read from source): mpObjStrBinaryOpImpl
(objstr.zig:842-932) reads ANY buffer rhs via
npyStrGetBufferRead (ext_mp_get_buffer -> C mp_get_buffer,
vendor/micropython_embed/py/obj.c:617); Add/Contains/all
comparisons use raw bytes. arrayBinaryOpImpl
(objstr.zig:358-434, vendor objarray.c:282-291, 369-376):
comparisons use typecode_for_comparison (BYTEARRAY -> 'B';
uppercase -> lowercase + unsigned flag); raw-byte compare
iff codes equal AND code != 'f'/'d' AND (op == EQUAL OR
is_unsigned); else bare NotImplementedError; non-buffer rhs
-> OBJ_FALSE for every comparison op. The Rust
array_binary_op already mirrors this.
== is SAFE from this fix: bytes_type_data has flags: 0
(no EQ_CHECKS_OTHER_TYPE), so obj_equal_not_equal never
calls the str slot for cross-type ==; the array/bytearray
slot or pointer comparison decides. All == cases probed
agree already (array vs bytes False, bytearray/memoryview
vs bytes True).
Reference truth table probed (all match after the fix):
bytearray+bytes -> bytearray, array('b')+bytes -> array,
bytes+array('b'/'h'/'i'/'l'/'q'/'H') -> bytes with
native-endian raw bytes; array('b'/'B') == bytes -> False;
bytearray == bytes -> True; memoryview == bytes -> True;
array('b') < bytes -> True; array('h'/'i') < bytes ->
NotImplementedError on ref (bare, aborts — Rust matches
via the array slot); b".." < array('h') -> raw-byte
compare; b"ab" + memoryview(b"cd") -> b'abcd'.

Fix B — bytearray str methods (item 2) + bytes.join (item 4)
+ bytes(iter(...)) + bytearray('str').
Root cause: bytearray had NO str methods wired — the
bytearray dict was built from ARRAY_METHODS only (append/
extend) in vm_types.rs. Vendor bytearray locals = the full
shared table minus trailing encode
(objstr.zig:3520-3614 array_bytearray_str_bytes_locals_table):
append, extend, hex, fromhex, decode, find, rfind, index,
rindex, join, split, splitlines, rsplit, startswith,
endswith, strip, lstrip, rstrip, format, replace, count,
partition, rpartition, center, ljust, rjust, lower, upper,
capitalize, title, zfill, isspace, isalpha, isdigit,
isupper, islower (str: body+encode only; bytes: hex+decode
+body; array: append+extend only; memoryview: hex only).
Changes:
(a) NEW arena-only array_raw_bytes (binary.rs) mirroring
buffer_bytes' Array arm incl. view chains.
(b) str_data_pool (objstr_a.rs) gained an Obj::Array arm
for bytearray typecode (1) ONLY — int arrays and

(c) new_str_of_type gained a bytearray arm allocating a

Fix C — str.format kwargs + %-format __int__ (item 3).
(1) kwargs_lookup (objstr_format.rs): the failure was NOT
the nested-spec recursion — the three positional nested
lines ("{:{}}", "{:{}{}{}}", "{0:{1}{2}}") already PASSED.
The failure is kwargs: "{foo}".format(foo="bar") raised
KeyError: foo. Cause: kwargs_lookup required the field
name to be a STATIC qstr (find_static_qstr), but kwarg
names from source (foo, text, align, width) are DYNAMIC
qstrs. Fix: compare kwarg-name BYTES through the pool
(pool.qstr_str(k.name as u16) == field_name) instead of
requiring a static id; the vendor interns the field name
(qstr_from_strn CREATES it) and compares ids — Rust
compares bytes, the same equality without interning.
(2) %-format __int__ dispatch: int(A()) ALSO fails on Rust
(TypeError "can't convert to int") — __int__ dispatch is
broken generally (E2 cluster (p) special_methods), not
just in %d. NEW modulo_int_value + call_int_maybe_hook
(objstr_format.rs): fast path int_value (small/heap ints,
bools); else run instance_unary_op(IntMaybe) through the
hook (the slot's instance_unary_op_slot uses stub seams
and cannot run FunBc). NEW public str_modulo_format_hook;
existing str_modulo_format delegates with None. NEW
MODULO branch in binary_op_ctx (vm_rt.rs, after the Equal
branch, before the generic loop): only when
obj_get_type(lhs) == str_ or bytes (exact — subclass
instances and instances with __mod__ keep the generic
loop; a str lhs with an instance rhs having __rmod__ is
unaffected because the str slot runs first in both paths);
creates the hook via make_hook(state), maps errors via
slot_raise then drain_hook_raise. %d/%i/%u AND %o/%x/%X
arms use modulo_int_value; %c does NOT (probed: %c does
not dispatch __int__ on the ref — TypeError "integer
needed" on BOTH). * width/precision use modulo_width_int
(probed: "%*d" % (A(), 42) and "%.*f" % (A(), 3.14159)
dispatch __int__ on the ref).
Probed edges (all match): __int__ raising ValueError
("boom") propagates; __int__ returning "x" raises BARE
TypeError (msg '', args () — finish_unary's BareTypeError
+ exc_from_pyerror rebuilding with no message when
nothing is stashed); "%o"/"%x"/"%5d" % A() -> 173/7b/
"  123". "{:d}".format(A()) raises ValueError "bad format
string" on the ref — str.format {:d} does NOT dispatch
__int__ (not a target, not changed).
Note: the first %*d test written for this lane reused a

§4 — Shortfalls, with per-case root causes
--------------------------------------------
(a) int(A()) still raises "can't convert to int" — the
GENERAL __int__ dispatch (E2 cluster (p) special_methods)
is a larger mechanism (the int() builtin /
obj_get_int_maybe path, used by int(), float()?, index(),
etc.); only the %-format path is fixed here. A lane
fixing int(A()) must thread a hook through
obj_get_int_maybe's callers or the int builtin — out of
this lane's scope (its brief is bytes/format).
(b) REFERENCE BUG — float arrays (documented divergence,
not fixed): the reference binary is fundamentally broken
for float arrays — print(array.array("f", [1.0])), len(a),
a[0], list(a), a + a, a == a, bytes(a), bytearray(a) ALL
raise TypeError "can't convert to int", and
bytes(array.array("f", [])) PANICS the reference (Zig
panic "cast causes pointer to be null" at objstr.zig:1901,
mp_obj_new_bytes(@ptrCast(bufinfo.buf),...) on a null
items pointer). Cause: bytesMakeNewImpl
(objstr.zig:1871-1937) — ext_mp_get_buffer fails for float
arrays so it falls to the iter path where mp_obj_get_int
(1.0) raises; the array-construction path calls
mp_obj_get_int on float items. Corpus never tests float
arrays in bytes positions (uses 'b'/'h'/'i'). Decision:
buffer_bytes serves ALL Array typecodes (raw bytes,
vendor-C/CPython semantics); Rust returns the raw bytes /
b'' instead. Same divergence class as C8a's.
(c) list_sort.py still fails on this lane's base
(b7f0b7e) — E2d's scope (user-class __lt__ sort +
container repr). E2d MERGED to master (67b7149) while
this lane ran, so it should now pass on master — NOT
re-verified on this lane's base; the merger's rebase +
gate run will confirm.
(d) Remaining E2 §4 clusters unchanged: (g) __set_name__
(E2f), (h) __reversed__/slice+range attrs (E2f), (j)
frozen deque (E2f), (n) descriptor / native-subclass
dispatch remainder, (p) misc (int_parse,
int_big_rshift, int_bytes_intbig, getitem,
import_instance_method, io_iobase, memoryerror,
ordereddict1, special_methods/__int__/__index__
dispatch, iter0/1/2), integration builtin-method kwargs
(E2f).
(e) test-stdlib test_abc, test_enum still fail (cluster
(n)).
(f) Integration remaining 25 fails are the known set
listed in §2 (no new mechanism among them is in this
