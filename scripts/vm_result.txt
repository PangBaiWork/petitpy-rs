Probed behaviours (reference binary ~/workspace/petitpy-orig/zig-out/bin/petitpy)
----------------------------------------------------------------------------------
- print(...)/repr(...) -> Ellipsis; type(...) -> <class ''>;
  ... == ... / ... is ... True.
- int.to_bytes always two's-complement ((-1).to_bytes(1,"big")
  -> b'\xff').
- print kwargs: sep=2 -> TypeError "can't convert to str
  implicitly"; unknown kw -> TypeError "argument num/types
  mismatch"; bytes sep accepted; print(1,2,sep="-") -> 1-2.
- record_raise returns (); list arity() returns bare PyRaise
  while dict check_arity returns typed DictError.
- gen_wrap_call returns (GcRef, CodeState); frame.ip stays at
  the opcode byte during the opcode, local ip written back at
  each opcode end; YIELD_VALUE sets ip past the opcode then
  yields; YIELD_FROM on sub-generator yield rewinds ip -= 1;
  UNWIND_JUMP pushes (dest, count byte); SETUP_WITH val_sp
  points at exit_self; WITH_CLEANUP 3 layouts (None / small-int
  / exception); END_FINALLY pops exc block, None -> pop,
  small-int <0 -> unwindReturn, >=0 -> push back + unwindJump,
  exception -> raise; fetch polls pending_raise FIRST;
  mp_obj_get_int_maybe guard (pending set -> conversions read
  0); mp_iternext pre-flight: pending set -> stop WITHOUT
  clearing.
- for i in range(n) is COMPILED to an optimised form
  (handlers_control.rs range recognizer) that never calls the
  range type — which is why `for i in range(5)` passed while
  `x = range(3)` raised "object not callable" (see §4).
- LOAD_CONST_SMALL_INT is a SIGNED varint: bit 6 of the FIRST
  byte is the sign; a set bit initialises the accumulator to
  all-ones (vm.zig:539-548). decode_int implements it; the
  unsigned decode_uint misread -100 as 16284.
- STORE_SUBSCR stack is [value, base, index] (index on TOP —
  the compiler pushes the value first; vm.zig:663-674); value
  == NULL is `del x[i]` (DELETE_SUBSCR = LOAD_NULL +
  STORE_SUBSCR). STORE_MAP is [dict, value, key] (key on top).
- mp_obj_subscr rule (obj.zig:604-605): a slot failure WITH a
  pending exception propagates THAT error; only a failure with
  NO pending error falls through to the generic raise
  ("object isn't subscriptable" / "object doesn't support item
  assignment"). exc_from_obj_error (vm_ops.rs) drains the
  pending raise first, else converts the ObjError.
- list_subscr / tuple_subscr dropped get_index errors (returned
  PyRaise without recording); fixed to record_typed (IndexError
  now surfaces instead of the generic TypeError).
- Dynamic qstrs (>= N_TOTAL, e.g. string literals from the
  module) cannot be resolved by the arena-only str_data
  (qstr_bytes is static-only). str_data_pool (objstr_a.rs)
  resolves Qstr through RuntimeQstr::qstr_str (static AND
  dynamic) and heap Str/Bytes through the arena; used by
  str_binary_op / str_subscr (objstr_methods_c.rs) and the %
  formatting + str.format paths (objstr_format.rs). The other
  ~50 str_data call sites (str methods, etc.) still use the
  arena-only form — same gap, out of this lane's scope.
- Generator throw/close/send interception: the four
  gen_instance_*_builtin stubs are byte-identical macro bodies,
  so the release linker folds them (ICF) and std::ptr::
  fn_addr_eq reports all four as equal — the first check
  (send) won for every call, misrouting throw/close as a plain
  send (the generator resumed normally and exhausted). Fixed by
  matching on the FunBuiltin NAME qstr + a generator first-arg
  check (vm_call.rs: call_fun_builtin_ctx).
- convert_member_lookup payload rule (C12a's lookup.rs fix,
  applied here to vm_rt_name.rs): FunBuiltin/FunBc are
  allocated with header None, so the header-type read cannot
  see BINDS_SELF. Payload check: FunBuiltin binds self unless
  found in an instance type; FunBc always binds self. Without
  this, a generator's throw/close/send loaded UNBOUND (self
  None) and the call passed the generator as an arg.
- gen.close() uses close_generator_ctx (gen_instance_close):
  a yield is RuntimeError("generator ignored GeneratorExit");
  a raise is swallowed iff it is a GeneratorExit; normal is a
  successful close. (The send/throw form
  resume_generator_value_ctx propagates the raise — wrong for
  close.)
- mp_resume (runtime.zig:1363-1456): a NON-generator resume
  uses `send` ONLY when the send value is non-None; a None
  send falls through to __next__. resume_vm_ctx previously
  routed every Some(send) through `send`, so `yield from [1,2]`
  raised AttributeError("no attribute 'send'") on the list
  iterator. Fixed: send path only when sv != Value::None.
- The `for` loop range recognizer, the compiler's
  optimised-range form, and the `list[str]` /
  `__class_getitem__` branch (needs runtime.typingCall, C14/C15)
  are NOT in this lane.

Intentional divergences
-----------------------
- A Str `**` key that was never interned cannot be created
  through the immutable CallCtx.pool — it raises
  TypeError("keyword argument name is not an interned string")
  instead of being silently dropped (the Zig interns it; a
  &mut pool on CallCtx would close the gap).
- `len(range(0,10,2**32)[::2**32])` — Rust returns 0, the
  original aborts rc=134 (pre-existing, C9c).
- The original crashes on five C8b inputs (center with
  negative width, huge widths) — Rust returns self/truncates
  (pre-existing, C8b).
- `deque([], 2**62)` aborts the original rc=134; Rust returns
  OutOfMemory (pre-existing, C11).
- A self-referential dict's repr crashes the original by
  infinite recursion; Rust mirrors it with no guard
  (pre-existing, C9a).
- `sort(key=len)` on ints aborts the original rc=134
  (pre-existing, C9b).
- `(a*)*` aborts the reference binary rc=134 (pre-existing, RE15).
- The original's complex constants are broken at runtime
  (print(4j) ValueError, complex(3,4) panics rc=134)
  (pre-existing, frontend).
- `98 in bytearray(b'abc')` raises bare NotImplementedError
  (pre-existing, C9b).
