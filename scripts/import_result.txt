Fixes found by this lane's own tests (all verified in-lane):

* Seam-drain bug (C14 contract): `exception_from_pending`
  reads only `ctx.take_pending_raise()` and never looks at
  `state.pending_exc`, so a seam-stashed exception fell through
  `exc_from_pyerror` to a bare TypeError. Evidence:
  `dispatch_import_error` failed with left "TypeError" vs
  right "ImportError". Fix: `import_name_ctx` /
  `import_from_ctx` map `RtError::PyRaise` via the existing
  `drain_seam_raise` convention in `vm_rt_iter.rs` (same
  pattern the iterator `call` seam uses). The C13 test
  `dispatch_import_error` now expects "ModuleNotFoundError"
  (the C13 stub raised a plain `ImportError`; with a real
  import system and no `os` module registered, `import os`
  raises ModuleNotFoundError, an ImportError subclass).
* Module-attr slot: the module type's `attr` slot was `None`
  in `module_type_data`, so `load_method_maybe` on modules
  returned `None` and from-import / dotted imports /
  `__path__` reads all failed (19 of the 49 import tests).
  Fix: `module_type_data` now sets `attr: Some(module_attr)`
  (`src/objects/objtype/objmodule.rs`; `module_attr` =
  `module_attr_load`, no `__getattr__` seam — a module
  `__getattr__` is still not called). This CLOSES C14's
  "D1 must set attr: Some(module_attr)" note — D1 no longer
  needs to wire it. C14's test Env manual assignment
  (`runtime_tests.rs:105`) is now redundant (kept, same fn).
* Qstr interning on the dispatch path (the blocker): the
  dispatch path could not intern new qstrs — `CallCtx.pool`
  is a shared `&RuntimeQstr` and `from_strn` took `&mut self`,
  so the C15a read-only fallback failed genuinely-new names
  with MemoryError. Every imported module defines new names,
  so this was not an edge case: a temporary debug probe proved
  the failing name was `"VAL"` in `py_module_identity` (the
  test source never mentions `VAL`; the first import of
  `m1.py` failed resolving its qstr table).
  Fix: dynamic bytes are now LEAKED (`Box::leak` → `&'static
  [u8]`) and the entry table is `RefCell<Vec<DynamicEntry>>`,
  so `from_strn` / `from_str` take `&self`. Soundness
  (documented in `qstr.rs`, divergence #2 updated): each
  entry's bytes live in their own heap allocation, so pushing
  to the entry table never moves an already-returned slice
  (the table holds only `&'static` pointers); `qstr_str`
  copies the `&'static` reference out from under a short-lived
  shared borrow, then shortens it to `&self`. The leak is
  bounded by the number of distinct dynamic names (≤255 bytes
  each); `reset()` uses `get_mut().clear()` — leaked buffers
  stay allocated, as the Zig's chunks do until `qstr_init`.
  `RuntimeQstr` is therefore `!Sync` (a `RefCell`); the VM is
  single-threaded, so nothing requires `Sync`. `from_strn`
  reserves the slot BEFORE leaking (a failed reserve leaks
  nothing). Consequences: the read-only fallback is DELETED
  (`resolve_one_qstr_readonly`,
  `resolve_one_qstr_readonly_u32`,
  `resolve_qstr_table_readonly` in `vm_eval.rs`;
  `resolve_table_readonly` in `import_search.rs`) —
  including the C15a eval gap for genuinely-new names.
  `resolve_qstr_table` moved from `vm.rs` to `qstr.rs` in
  the same change (it is a qstr utility). One C15a test was
  updated for the new behaviour: `eval_dispatch_new_name_fails_loud`
  → `eval_dispatch_new_name_interns`, now asserting
  `NameError` (the name interns; the variable is unbound —
  the original's behaviour).
* `vm.rs` split: the lane pushed `vm.rs` to 825 lines, over
  the 800-line cap. `resolve_qstr_table` moved to `qstr.rs`
  and `set_sys_path` / `set_frozen_modules` moved to
  `vm_eval.rs` (new `impl Vm` block) — `vm.rs` is 787 lines

Design decisions that changed since §1–§3 were written:

(a) `raw_code_load_mem` takes a parsed `mpy::Module` and
    returns header failures via `VmError::Raised` (the
    exception object itself), not `pending_exc` + OutOfMemory.
(b) The C14 seam's stashed exception is drained via
    `drain_seam_raise`, NOT `exc_from_pyerror` (which only
    sees `ctx.pending_raise`).
(c) `from_strn` now takes `&self` (leak + RefCell) so
    dispatch-path imports intern for real — the read-only
    fallback is deleted.
(d) `module_type_data` now wires `attr: Some(module_attr)` —
    C14's D1 note is closed.
(e) `import_impl` does NOT validate globals/locals/fromlist
    (verified against the Zig — an earlier plan guessed a
    dict check, wrong). It reads only `args[0]` (name),
    `args[3]` (fromtuple, default `None`), `args[4]` (level,
    default 0). Level: only `SmallInt(0)` passes; ANY other
    REPR_A word (heap pointer, qstr, `None`, `True`) is
    non-zero → NotImplementedError "relative import". Return:
    `fromtuple is None` → TOP module, else LEAF (any
    non-`None` fromlist — even `()` — returns the leaf;
    diverges from CPython; the opcode path never passes an
    empty tuple). The dotted walk is the Zig's index loop
    (`i` from 1 — a leading `.` is NOT a separator, so
    `".foo"` is one component `".foo"`; `"a..b"` yields
    `"a"`, `""`, `"b"`).
(f) `register_loaded_into` registers already-loaded code
    under an EXISTING module object (no new module, no
    re-registration) — the import loader's `execMpyInModule`
    path; `state.modules` holds the same object the first
    `import x` returned.
(g) `load_found`: a FilePy/FileMpy read failure raises
    ImportError "module not found" — the Zig returns a bare
    PyRaise with NO pending exception here (a TOCTOU wart,
    documented). A PRESENT-but-unreadable `__init__.py`
    returns silently WITHOUT trying `__init__.mpy` (the
    Zig's `return` sits inside the `pathIsFile` block).
    Namespace packages (no `__init__.py`) are OK.
(h) `new_module` sets `__name__` but does NOT register in
    `state.modules` — `try_load_component` inserts BEFORE
    `load_found` (circular-import + failure-removal
    semantics) and `remove_from_loaded` deletes on failure.
