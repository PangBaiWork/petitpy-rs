INTENTIONAL DIVERGENCES (documented in code, not silent)
--------------------------------------------------------
1. e.args returns a FRESH tuple per access (ExceptionData.args is
   Vec<Value>, frozen); 0-arg args is a fresh empty tuple, not the
   ROM () singleton (C12a's ROM work).
2. exception_match on immediates returns false (observably
   equivalent — immediates are never exception instances).
3. PRINT_EXC_SUBCLASS (0x80) not plumbed (no Instance yet — the
   vendor sets it only in objtype.c:271 for user-subclass
   exception inner print).
4. Emergency-exception-buffer fallback is dead (Rust alloc is
   infallible).
5. Module delegation (npy_mod_attr_try_delegation,
   MICROPY_MODULE_DELEGATIONS table) has no Rust counterpart yet:
   load/store report not-found/unhandled where the Zig consults
   the table. No delegation table exists in the tree (C15/D own
   extension modules).
6. object_make_new / object_new / object_setattr / object_delattr
   validate their checks, then return PyRaise where the Zig
   touches the Instance members map / allocates (no Instance
   payload yet — C12a's mp_obj_new_instance). object.__new__ is
   stored as a plain FunBuiltin; the staticmethod wrapper is
   C12a's (mp_type_staticmethod).
7. The `__file__` qstr is NOT static (config-gated out of the
   static table; main.zig:148 — interned dynamically at runtime),
   so module_print finds the __file__ entry by scanning the dict
   for a key whose string is "__file__" (dict_lookup_by_str),
   not by id lookup. The old static_qstr_id(b"__file__").expect()
   would have panicked at runtime — caught by the test suite.
8. Value::Qstr ids are u32; RuntimeQstr::qstr_str takes Qstr
   (u16) — all call sites cast `as u16` (codebase convention).
9. Dynamic qstr interning needs &mut RuntimeQstr, which CallCtx
   does not carry: module_get_builtin takes an `intern` seam
   (None skips the u-prefix strip); the __getattr__ and __init__
   call seams are likewise optional (None skips the call).
