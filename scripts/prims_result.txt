VERIFIED CORRECTIONS / DIVERGENCES (all probed on the reference binary)
1. bool is NOT an int subclass (brief premise + design-doc D8 wrong):
   isinstance(True,int)==False, issubclass(bool,int)==False. Neither
   type has a parent slot; mp_obj_is_subclass only special-cases object.
   int/bool/cell base=None, mro=[self]. Bool->int exists only in
   arithmetic delegation (slots convert to small int 0/1).
2. mp_arg_check_num_sig is POLLED-ONLY (argcheck.zig:100): make_new never
   checks it. Branch error wins, else pending TypeError surfaces:
   int(1,2,3)->ValueError invalid syntax; int("42",10,99)/int(1,x=1)/
   int(x=1)->TypeError argument num/types mismatch. Same rule in
   bool_make_new.
3. int(x, base): base truncated i64 -> c_int (verified: int("42",2**40)==42
   [base 0], int("ff",2**32+16)==255 [base 16], int("42",2**31)->range err).
4. int(non-str, base) -> ValueError invalid syntax for integer (NOT
   TypeError): Zig str_get_data is polled (sets pending TypeError,
   returns NULL/len 0); make_new does not check NULL; the empty parse
   overwrites pending_exc. Ported as the observable ValueError.
5. int("42","10") / int("42",10.0) -> TypeError can't convert to int
   (float INT_MAYBE is NULL); int("42",2**70) -> OverflowError
   overflow converting long int to machine word.
6. pow(2,3,0) -> ValueError divide by zero (NOT ZeroDivisionError);
   pow(2,3,True) -> TypeError pow() with 3 arguments requires integers
   (bool excluded); 0**-1 -> ZeroDivisionError divide by zero.
7. to_bytes: small ints use the Zig clz/slen + mp_binary_set_int path.
   Heap ints use Lane C as_bytes (vendor mpz_as_bytes verbatim) WITH its
   quirk: overflow bytes must be 0x00, so negative heap ints need
   ceil(digits*32/8) bytes, not the minimal length: (-(2**70)).to_bytes
   (9/10/11) all OverflowError, (12) succeeds (b'\xff\xff\xff\xc0...').
   DIG_SIZE is 32 on x86-64 (vendor MPZ_DIG_SIZE), not 30.
8. int("010",0) -> ValueError (base 1); int("010") base 10 -> 10.
