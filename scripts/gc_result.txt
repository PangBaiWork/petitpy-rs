Key findings (all verified against the original, not guessed)
-------------------------------------------------------------
1. THE BRIEF'S PREMISES WERE WRONG IN FOUR PLACES (all checked by grep):
   - `gc_free_all` does NOT exist — not in gc.zig, not in petitpy src/,
     not in vendor py/gc.c. The actual function is `freeAreas()`
     (gc.zig:145), ported as `free_areas()`.
   - `gc_dump` / `gc_debug` / `gcCollectDebug` do NOT exist in gc.zig.
     Its only diagnostic is `gc_info`, ported as `info()`.
   - There is NO `GC_THRESHOLD` / `gc_alloc_amount` mechanism in gc.zig.
     The vendor threshold rule (py/gc.c:787-788, 880: collect when
     gc_alloc_amount >= gc_alloc_threshold) was NOT carried into gc.zig.
     gc.zig's only count-based trigger is the stress rule (NPY_GC_STRESS
     -> stress_every; allocWith gc.zig:490-493). Rust `threshold` is
     therefore the STRESS control (collect every N allocations), per the
     C0 design doc D6 ("原版 alloc_count 规则"). Python-visible
     gc.threshold() (modgc.zig) is a separate no-op that ignores its
     argument — the D lane must NOT wire it to this field.
   - `gc_mem_alloc` / `gc_mem_free` do NOT exist as functions in gc.zig.
     modgc.zig's mem_alloc/mem_free read gc_info().used / gc_info().free,
     so Rust mem_alloc()/mem_free() are exactly info().used / info().free
     (live / free slot block bytes).
2. `gc.collect()` returns 0 ALWAYS in the original (modgc.zig:
   "PY_GC_COLLECT_RETVAL=1: collect() returns int(gc_collected). The
   bumping gc.zig allocator never sets gc_collected; always 0").
   gc.zig's gc_collect() returns void. The Rust collect() -> usize
   (freed count) is the frozen C0 API (CPython-like); the D-lane gc
   module must return 0 from Python gc.collect(), NOT this count.
3. HEADER-TYPE TRACING — C0 BUG FIXED (grounded in gc.zig): gc.zig's
   scanRange follows EVERY word of a live allocation, including its
   first word = the type pointer (MpObjBase.type). The C0 skeleton
   traced only Obj::children() (payload), so a type reachable only
   through instance headers could be freed while its instances
   survived. collect_inner now also marks header.type_. Test
   `header_type_is_traced` pins it (type + dict survive via the
   instance header alone). Frozen API untouched.
4. SKELETON TRIGGER RULE CORRECTED: C0's alloc() collected when
   `alloc_count >= threshold` (collect-once semantics). The original
   rule is the stress modulo (`alloc_count % stress_every == 0`,
   gc.zig:490-493), gated by autoCollect() (lock_depth == 0 and
   gc_auto_collect_enabled != 0). alloc() now implements the modulo
   rule; alloc_count keeps its frozen meaning (since last collect).
   gc.zig's alloc_count is monotonic (never reset by collect); Rust
   keeps a separate monotonic `stress_alloc_count` for the rule so
   the phase survives explicit collects. Test `threshold_stress_…`
   pins the phase across collects.
5. FINALISERS — MECHANISM CHANGED, OBSERVABLES KEPT: gc.zig's
   runFinalisers calls __del__ between marking and sweeping, with the
   GC locked and `finalising` set (blocks allocated by a finaliser are
   created marked). The Rust arena cannot call __del__ (needs the VM's
   call machinery, mp_call_function_1_protected). Instead collect()
   clears the flag first (as gc.zig does), marks the object + its
   transitive children live for this collection (children intact for
   __del__), and lists it in `pending_finalisers`; the VM drains the
   list, runs __del__ through its normal call path, then frees each
   object. Consequences, all documented in gc.rs: no `finalising`
   field (allocations during __del__ are ordinary VM-rooted allocs);
   pending_exc save/restore is the VM hook's job (pending_exc lives
   in VmState, C13); resurrection becomes possible (gc.zig would still
   free the object) — unobservable for native types, the only
   finaliser users. Typeless objects are skipped (gc.zig: "no type
   yet"), freed by the sweep — test `finaliser_typeless_skipped`.
   Flag cleared on listing, so a finaliser runs at most once.
6. realloc DIVERGENCES (documented in code): Rust slots have no
   neighbouring blocks, so growing in place always succeeds and the
   ref is always preserved — `allow_move` never triggers a move
   (gc.zig checks the following blocks are free). `realloc(r, 0)` frees
   and returns None (gc_realloc rule); `alloc::realloc(buf, 0)` keeps
   an empty buffer (m_realloc goes through reallocMaybe, 1-block
   minimum) — the two originals genuinely differ, both ported.
7. `collect()` LOCKS: the C0 skeleton's collect() ignored lock_depth.
   It now returns 0 when locked (gc.zig gc_collect: `if (lock_depth
   != 0) return`), while the internal collect_inner() has no lock
   check (callers guarantee it, as in gc.zig).
8. auto_collect_enabled lives on the arena (it is mpstate.zig
   StateMem.gc_auto_collect_enabled, u16 at offset 568, set to 1 by
   gc_init, poked by modgc enable/disable/isenabled). When the C15
   mpstate lane arrives it must NOT duplicate this field — the arena
   owns it. `GcArena::new()` builds a post-gc_init arena (enabled,
   threshold -1); `gc_init()` re-applies the init effects (env var).
9. Block accounting scope (known limitation, C0 design): Rust-heap
   buffers inside payloads (Vec contents) live outside the arena,
   unlike the original where every buffer is a GC allocation, so
   mem_alloc() counts object slots only (block-rounded). The per-slot
   block math itself is exact (see probe).
