Bugs found in earlier phases' code (fixed here)
-----------------------------------------------
1. A1 grammar_data.rs::get_rule_arg sliced to `act & mask` entries,
   but for LIST rules the act's low nibble is the *flavour* (1=list,
   2=one_or_more, 3=list_with_end), not a count — 13 LIST rules with
   flavour 1 (or_test, and_test, comparison, expr, xor_expr, and_expr,
   shift_expr, arith_expr, term, dotted_as_names, dotted_name,
   name_list, with_stmt_list) each carry 2 arg entries but A1
   returned 1, so the parser would have indexed rule_arg[1] out of
   bounds. Added rule_arg_count(id) (LIST: one_or_more→1, else 2;
   AND/OR→act & mask) and made get_rule_arg use it. grammar_data
   tests now 6/6 (incl. list_rule_arg_counts: or_test separator is
   KW_OR = token 42). Also corrected the A1 spot check: file_input_2
   is a one_or_more LIST rule (1 entry [0x203f]).
2. Zig pushFoldedIntResult's comment says "30-bit SMALL_INT" but the
   code calls fitsSmallInt — the 62-bit window. First zigdiff run
   diverged on 10 files (folded -10^18, 0xffffffff & results, etc.);
   fixed the Rust push_folded_int_result to the 62-bit window and the
   diff went 552/552. The bare-literal path (makeTokenPn) keeps its
   30-bit gate — the asymmetry is real Zig behavior, ported verbatim.
3. Brief errors corrected against the Zig source (not ported):
   `qctx.getText(tok)` does not exist — the token text is lex.vstr;
   validateIntLiteral takes raw bytes and returns void (not a Pn);
   the mainloop reads grammar_ext::rule_act/get_rule_arg, not the
   vendor tables; AND/LIST branches push ONLY NAME/item tokens via
   pushResultToken (the full makeTokenPn dispatch), not every token.

Design decisions (do not re-decide without cause)
--------------------------------------------------
- Arena, not chunk allocator: ParseTree owns Vec<ArenaNode>; Pn =
  (arena_index << 2) (index 0 reserved, so Pn 0 == PN_NULL); leaf /
  small-int / null tag encoding identical to Zig; const-object
  nodes[2] always 0, payload in the arena entry's payload field.
- Scope arena: ScopeArena { scopes: Vec<Scope> } with ScopeId
  handles; parent/next are Option<ScopeId>; raw_code is usize
  (0 = null); find/find_or_add return IdInfo indices (stable across
  growth, unlike the Zig *IdInfo pointers); find_global returns
  (ScopeId, usize). Tests port assertions verbatim; only
  construction/linking syntax changes. Rationale: Rc<RefCell>
  would double-borrow-panic in check_to_close_over (holds an IdInfo
  handle while mutating the same scope).
- find_or_add growth matches vendor exactly: pre-size to 4, grow by
  exactly +6 via reserve_exact (4 → 10 → 16 → 22).
- parse_node_is_const_bool is a ParseTree method (needs the arena);
  parse_node_extract_list returns an owned Vec<Pn> (Zig returns a
  pointer into the node/slot for in-place mutation — the compile
  phase will need a mutable-access variant; noted, not built here).
- Scope pin-checks (six simple_name qstr ids) are Rust tests, not
  comptime asserts (QSTR_STRINGS is a static).
- grammar_ext rule names stay lowercase (RULE_match_stmt, ...) to
  match the Zig identifiers; grammar_ext.rs carries
  #![allow(non_upper_case_globals)] like grammar_data.rs.
- is_positive() = !neg (true for zero, per Zig probe) — decides the
  bitwise-fold gate.
- Power (**) IS implemented in the big-int fold (bigint::BinOp::Pow,
  MAX_POW_EXPONENT 4096 cap) — the brief's "deferred" note was stale.

Divergences from the Zig original (all deliberate, documented)
--------------------------------------------------------------
- Arena instead of chunk bump allocator (above); const-object
  nodes[2] = 0 always (payload in arena entry).
- ParseError is its own enum (OutOfMemory/SyntaxError/
  IndentationError/DedentMismatch), not PyError.
- Scope arena design (above); find returns an index, not a pointer.
- peek_rule returns 0 when the stack is too short instead of
  asserting (safe fallback; the fold it guards then doesn't fire).
- parse_source convenience helper was NOT ported (not in Zig).
- The `match` soft-keyword hook, doc-string discard
  (ENABLE_DOC_STRING=0 → bare string expr_stmt becomes pass_stmt),
  and_ident / and_blank handling are ported verbatim.

What did NOT port cleanly / is deferred
----------------------------------------
- Nothing in scope is unported. The 54 ported test blocks all pass.
- parse_node_extract_list's in-place mutation semantics (pointer
  into the node/slot) are NOT available in Rust yet — the owned-Vec
  form is sufficient for the parser and scope; the compile phase
  (Phase B/C) will need a mutable-access variant.
- The empty-file test stays #[ignore] (stale upstream expectation).
