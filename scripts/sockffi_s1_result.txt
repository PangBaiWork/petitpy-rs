§2  Design decisions (beyond the brief, recorded)
-----------------------------------------------
- FFI getsockopt/setsockopt use the SockSettings shadow
  as source of truth (pinned tests require it:
  SO_PEERCRED -> ENOPROTOOPT, unset RCVBUF/SNDBUF ->
  ENOPROTOOPT, RCVBUF set -> exact value — the kernel
  doubles it to 8192, so the shadow must answer);
  setsockopt ALSO lands in the kernel via an apply_opt
  FFI arm (real effect). FfiSocket::getsockopt exists
  for internal use only (SO_ERROR in connect_timeout).
- FfiSocket has a `bound: bool` field (kernel
  auto-binds INET listen; UNIX double-bind gives
  EADDRINUSE not EINVAL — pinned behaviour is EINVAL
  for both) and a `listening: bool` field (for
  is_listener). from_raw sets bound=true.
- modsocket.rs holds the socket-table lock across FFI
  calls (including blocking ones) — safe in this VM
  because Python execution is single-threaded and only
  the VM thread ever takes the table lock (readiness
  monitors use their own table); documented in
  modsocket_ffi.rs header.
- AF_UNIX works through FFI on Unix in S1 (generic
  SockAddr machinery) — S3's AF_UNIX scope reduces to
  the Windows probe + dedicated tests. The AF_UNIX-on-
  Windows construction check (NotImplementedError) is
  left as-is for S3.
- Module constants stay Linux-numbered
  (Python-facing); translation happens at the FFI
  boundary. Changing them to platform-correct values
  would change default-build behaviour on macOS/
  Windows — out of S1 scope.
- sys_ioctlsocket declared in S1 (setblocking needs
  it) though brief §2.1 said S3.
- SockaddrUn::len_for now takes the path (not just
  its length): abstract addresses (leading NUL) are
  NOT NUL-terminated (length 2 + len), filesystem
  paths get the trailing NUL (2 + len + 1).
- SockAddr::from_raw returns an empty Unix address
  (path []) for an unnamed peer (kernel sets addrlen
  0) instead of None -> EINVAL. Verified: pure-Rust
  std reports the same peer as unnamed
  (as_pathname() == None) — Linux does NOT autobind
  an AF_UNIX datagram socket here (neither connected
  send nor unconnected send_to), so the abstract
  case does not arise on this kernel; the abstract
  handling is defensive and correct.
- SocketState::set_nonblocking/set_timeouts and
  apply_settings now take &mut self / &mut SocketState
  (the FFI setters update FfiSocket shadow fields);
  call sites (swap_in, sock_accept, sock_dup,
  sock_setblocking, sock_settimeout, setsockopt
  timeout arm) switched to get_mut.
- The `socket_fileno_changes_on_bind` lib test was
  updated (see §1) because it pinned the placeholder
  behaviour that S1 intentionally removes under the
  feature build.

§3  Tests
---------
New file tests/sockffi_core.rs (feature build only):
  cargo test --release --features unsafe-ffi --test sockffi_core
  => 9 passed, 0 failed, 2 ignored.
  Live: fileno stable across bind; TCP bind/listen/
  accept/connect roundtrip + send/recv; TCP accept
  (VM server, Rust client, port via file);
  AF_UNIX datagram sendto/recvfrom (client binds so
  the VM can reply); AF_UNIX datagram from an UNBOUND
  peer (recvfrom returns (b'ping', b''), not an
  error); setsockopt/getsockopt (SO_REUSEADDR,
  TCP_NODELAY, SO_RCVTIMEO 16-byte timeval);
  connect with a timeout set (exercises
  connect_timeout's nonblocking + poll path, succeeds
  against a listener); shutdown + getpeername/
  getsockname (SHUT_WR -> peer sees EOF); dup (new
  fd, still sends after the original is closed).
  Ignored (sandbox): AF_INET UDP roundtrip and the
  blackhole connect timeout (ETIMEDOUT) — the sandbox
  returns EPERM for UDP loopback sendto and for any
  non-loopback connect (verified with standalone std
  probes: UDP send_to -> EPERM errno 1; connect to
  10.255.255.1 -> PermissionDenied raw=Some(1) in
  42us). Run with `-- --ignored` on an unsandboxed
  host.
  Note: petitpy's getsockopt REQUIRES a buflen and
  returns bytes (no int form); the first version of
  the test called it with 2 args and failed with
  TypeError "argument num/types mismatch" — a test
  bug, not an implementation bug. Fixed to pass
  buflen and compare bytes.

§5  Leftover issues / for S3 (and the merger)
----------------------------------------------
1. Feature lib has ONE failure:
   modules::modsocket_tests::socket_makefile —
   makefile() on an FFI socket returns EINVAL
   (sock_makefile's match falls into `Some(_) ->
   EINVAL` for the Ffi variant). This is the brief's
   documented S3 scope ("makefile naturally returns
   EINVAL for Ffi"); implementing it needs
   File::from_raw_fd (unsafe) to build the
   socketfile wrapper, which the brief reserves for
   S3. Default build is unaffected (1771/0/2).
2. Windows/macOS/Android branches are UNVALIDATED
   locally (no local cross-compilation per the CI
   constraint; the CI workflow still gates unsafe-ffi
   to the Linux rows only). The code is cfg-correct
   by construction (checked by reading), but no
   Windows/macOS/Android build or run was done here.
3. AF_INET UDP test and the blackhole connect-timeout
   test are #[ignore]d (sandbox EPERM, see §3).
   The ETIMEDOUT branch of connect_timeout is
   therefore untested here; the nonblocking + poll
   path IS tested (connect with timeout, §3).
4. Module constants stay Linux-numbered
   (Python-facing); translation is at the FFI
   boundary (see §2). S2/S3 should not "fix" the
   constants without a default-build behaviour
   decision.
5. `listening` and `bound` fields on FfiSocket were
   added beyond the brief's §2.3 struct (needed for
   the pinned EINVAL behaviour and is_listener).
   sys_ioctlsocket was declared in S1 though the
   brief said S3 (setblocking needs it).
6. getpeername/getsockname/shutdown are feature-only
   methods (no std implementation); on the default
   build those attributes do not exist on sockets.
7. Cargo emits "output filename collision"
   warnings for libpetitpy_rs during `cargo test`
   builds (pre-existing, also on the base — a cargo
   packaging quirk, not from this lane; it does not
   fail the build).
8. The feature build overwrites target/release/
   petitpy-rs; always rebuild the default binary
   (`cargo build --release`) before running default
   gates/probes (acceptance-order artifact — observed
   again in this lane).
