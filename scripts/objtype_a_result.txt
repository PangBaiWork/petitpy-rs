INTENTIONAL DIVERGENCES (documented, not hidden)
-------------------------------------------------
- `object()` is an Instance (empty members, no subobj), not a
  bare MpObjBase — observationally identical (see D4 note).
- The `__init__`-via-wrapper tail-skip proof is UNTESTABLE at
  this layer: a builtin __init__ never receives self (UNBOUND —
  BINDS_SELF|BUILTIN_FUN -> staticmethod), so it cannot call the
  wrapper; it needs a real Python __init__ (C13's job). The skip
  branch is code-reviewed and documented; the corpus will
  exercise it end to end once the VM runs.
- instance_binary_op's NotImplemented -> NULL is unrepresentable
  in Rust (no NotImplemented Value): the member's result is
  returned as-is; C13's Value-model decision.
- instance_subscr's __missing__ member call uses the bound pair;
  a NULL/SENTINEL __missing__ leaves the KeyError standing.
- The `__set_name__` call ORDER is insertion order in Rust vs
  map-slot (hash-table) order in the Zig — the order across
  descriptors is unspecified in both; only the snapshot
  semantics are pinned.
- `new_type`'s name extraction: a heap-Str name neither static
  nor already in the pool reports OutOfMemory (cannot intern
  without the VM's &mut pool — C13 gap).
- The wrapper FunBuiltinVar's n_args max is 255 (fun_n_args
  packs u16; the Zig's 0xffff is unrepresentable).
- `super()` / `type()` missing args are modelled as None
  (observed Arg2 error in both cases — the polled model).
- cast_to_native_base on a subobj-less instance returns None;
  the Zig reads subobj[0] unconditionally (UB there).
- A heap-Str class name that is neither static nor in the pool
  cannot be interned yet (C13 gap, see above).
- Type hash seeds are arena indices, not the reference binary's
  link addresses (22815552 / 22810192) — the structure (seed +
  wrapping sum + tag-wrap) is identical, and hash(()) ==
  id(()) holds in Rust too now.
- `new_empty_bytes` returns the singleton, but the .mpy reader's
  empty-bytes const path is the bridge's job (C13) — literals
  are const-deduped by the compiler, so `b'' is b''` holds via
  the const table regardless.
