## §1. What was built

New shared FFI module `src/support/ffi.rs` (133 lines, `pub mod ffi` in
`src/support/mod.rs`) — hand-written `extern "C"` declarations, zero
dependencies, G0's pattern (private `ffi` mod, `pub fn` wrappers used
as `crate::support::ffi::sys_*`). Wrappers: `sys_umask(u32) -> u32`
(infallible), `sys_close(fd) -> Result<(), i32>`,
`sys_fsync(fd) -> Result<(), i32>`,
`sys_lseek(fd, pos: i64, whence: i32) -> Result<i64, i32>`. Errno is
read via `__errno_location()` (glibc, same on x86_64/aarch64).
`__errno_location` is deliberately duplicated from G0's modselect.rs
(commented as such — same symbol, two private mods, no shared
coupling). Every `unsafe` block carries an FFI-invariant comment
within 3 lines above it.

U2 — `os_umask_builtin` (`src/runtime/modos.rs`): under the feature,
`arg_int(ctx, args[0])? as u32` into `sys_umask`, returns the previous
mask as a small int. Default build keeps the NotImplementedError stub
(the `not_impl` helper is now `#[cfg(not(feature = "unsafe-ffi"))]`
— it had no caller on the feature build and produced a dead-code
warning). `os.umask(-1)` wraps (`as u32` -> kernel masks to 0777);
the reference ABORTS (Zig `@intCast` panic, rc=134) — N1, not
reproduced.

U3 — `os_close_ctx` (`src/runtime/modos_fd.rs`): under the feature,
the real `close(2)` runs FIRST for every fd, then the table entry
is dropped (the drop re-closes the number, EBADF ignored) and the
stdio record is kept. Two consequences of "close by number, like
the reference": (a) an unregistered fd (an `open()` file's fd) and
stdio 0–2 really close, so the number is freed for reuse;
(b) a registered fd whose number was already closed out from under
it (e.g. by an `open()` file's `close()`) fails EBADF instead of
returning Ok — this corner was FOUND by the stale_fd_reuse probe
(the brief said to keep the registered arm as-is; the probe showed
the as-is arm returned Ok where REF raises, so the arm now runs
the syscall first too). Double close of a recorded stdio fd still
returns EBADF via the record check (the syscall never runs twice).
Default build: old shape verbatim (record-only stdio, EBADF for
unregistered fds).

U9 — `os_lseek_ctx` / `os_fsync_ctx` (`src/runtime/modos_fd.rs`):
under the feature, the stdio branch (fd 0–2) calls the real
`lseek(2)` / `fsync(2)`, so a stdio fd redirected to a regular
file seeks/syncs; on pipes/ttys the kernel returns ESPIPE /
EINVAL, exactly the old answers. Registered-fd arms unchanged
(std `seek` / `sync_all`). Default build: stdio lseek always
ESPIPE(29), stdio fsync always EINVAL — unchanged.

## §4. Leftovers / notes for the main agent

1. **Default build keeps the old gaps by design** (feature-gated
   work): umask stub, close only for `os.open`-tracked fds,
   stdio fsync EINVAL / lseek ESPIPE. The integration gate on
   the default build is unaffected (no integration case covers
   these).
2. **`os.umask(-1)` wraps, REF aborts** (N1) — documented in
   the code comment, the probe, and README; do not "fix" into
   an abort.
3. **In-process tests must never really close fd 0/1/2** (see
   §1, the `os_fd_roundtrip` flake): any future U-test that
   closes a stdio fd belongs in `tests/g6a_os.rs` (subprocess),
   not in a lib test. Same for `os.lseek(1)` assertions — the
   outcome depends on what fd 1 is in the test process
   (libtest capture file vs pipe).
4. **One transient cargo panic-strategy race** hit once during
   the lane (`error: the crate petitpy_rs requires panic
   strategy abort ... incompatible with unwind`, bin test
   target) — plain rerun fixed it, same as G2/G3 §4. Not a
   code issue.
5. **G6b reuses `src/support/ffi.rs`** — add `socket`/`fcntl`
   externs there (same pattern: private `ffi` mod, `pub fn`
   wrappers, invariant comment per `unsafe` block). The
   `__errno_location` duplication with G0's modselect.rs is
   intentional (documented in the module comment).
6. **P7b rides last** (unchanged): `ppy_exec` non-UTF-8 filename
   still lossy. Untouched by this lane.
