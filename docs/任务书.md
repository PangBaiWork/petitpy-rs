## 三、剩余工作总表（约 40,000 行 Zig + 2,040 行 vendor C）

### 3.1 关键设计决策（主 agent 冻结，见 `docs/value-obj-design.md`）

原项目的值模型是 C 互操作层：`Obj = usize`（REPR_A 标签指针：小整数
`(n<<1)|1`、62 位窗口、立即数 `OBJ_NONE=6 / OBJ_FALSE=14 / OBJ_TRUE=30`），
`mp_mirrors.zig`（1,082 行）用 `extern struct` 镜像 C 结构体，
`obj.zig` 用 `@cImport` + `extern fn` 调 vendor C。

**Rust 里没有 vendor C 可供镜像，因此不移植 `mp_mirrors.zig` 本身，
而是按其语义定义原生 Rust 值模型**：`Value` 枚举（内联立即数 +
GC arena 句柄）、`Obj` 枚举（全部对象种类）、`GcArena`（mark-sweep，
不移动对象）、显式 GC 根（Rust 栈不可保守扫描，VM 的值栈、全局量、
mpstate 必须显式登记为根）。行为（isinstance、hash、相等、repr、
异常语义）必须与原版一致；内部表示（指针标签、结构体布局）不要求
与 C 相同，`.mpy` 格式不编码对象布局。

- **C0（主 agent 亲自做，最先）**：Value/Obj 接口设计 + 骨架
  （`src/objects/value.rs` + `src/memory/gc.rs` 骨架 + 设计文档）。
  冻结后 Phase C/D 的 lane 才能开工。C0 不等任何 lane。
- **qstr 统一**：编译器 qstr（A1）与运行时 qstr（C1）共用一张表
  （已验证同号）；运行时 qstr 的注释声称 N_MAIN=216 是 stale 的，
  以实测 385/613 为准。
