MASTER BUG 1 — `*args` tuple and `**kw` dict allocated with
header type None (src/runtime/bc.rs, setup_code_state, C5/C13):
  The `**kw` dict was allocated with `ctx.alloc(None, ...)` at
  two sites (the n_kw/DEFKWARGS branch and the no-kwargs
  branch), and the `*args` tuple the same way. `obj_get_type`
  returns None for them, so every type-dispatched operation
  broke: len(kw) → "object has no len", `not kw` → False for
  the EMPTY dict, len(args) → "object has no len", args[0] →
  "object isn't subscriptable", and `**kw` unpacking fell into
  the slow path (vm_call.rs:594-598) that loads `.keys()` on
  the dict → AttributeError "no attribute 'keys'".
  Diagnosis path (kept in the result for the record): json.loads
  failed with AttributeError 'keys' for EVERY input although
  _json.decode worked directly and a replica of the loads body
  passed; a debug backtrace hook in new_exception_msg showed
  load_method_ctx ← call_method_var_kw_ctx ← dispatch inside
  loads; a second hook showed the object was a Dict (the kw
  dict, GcRef(566)) with obj_get_type == None; temp tests then
  proved `not kw` is False and len(kw) fails for the empty
  kwargs dict. The frozen json.loads/dumps were the first
  callers to hit it (`if not kw:` + `_Decoder(s, **kw)` /
  `(cls or JSONEncoder)(**kw).encode(obj)`).
  FIX (3 one-line changes in bc.rs): allocate with
  Some(ctx.types.tuple) / Some(ctx.types.dict). Pinned by 5
  regression tests (d5_varargs_tuple_len/subscr,
  d5_varkw_not_empty/len/unpack).

MASTER BUG 2 — str methods read dynamic-qstr literals through
the arena-only `str_data` (src/objects/strings/objstr_methods_a.rs,
the C13-class dynamic-qstr gap, ~50 sites tree-wide):
  `str_data` resolves a Qstr via the STATIC table only; a
  dynamic qstr returns None → StrError::BadImplicitConversion
  → TypeError "can't convert to str implicitly". D5 hit it in:
  (a) str_join — `"|".join(...)` failed because the separator
      "|" is a dynamic qstr (2 sites: separator + items);
  (b) str_startswith — enum.py's `name.startswith("_")` failed
      (subject `name` from dict keys + prefix "_" are dynamic).
  FIX: all 14 arena-only sites in objstr_methods_a.rs now use
  str_data_pool (join, get_substring_data, str_finder,
  str_startendswith, str_replace, str_split, str_rsplit,
  str_uni_strip) — same fix shape as D1's len('abc') and C13b's
  str_equal. Remaining sites in methods_b.rs (6: caseconv/
  capitalize/zfill) and methods_c.rs (1) are NOT fixed — see §4.

D1 GAP — `reversed` builtin missing: the original registers it
  in modbuiltins.zig:1082, but the Rust builtins table lacked
  it (C11 built the iterator machinery but no type object or
  binding). Frozen heapq.heapify uses `reversed`, so
  `import heapq` raised NameError. FIXED in D5 (see §1):
  reversed_type_data + reversed_make_new_slot + VmTypes.reversed
  + build_builtins bind. The slot's IterSeams are stubs (a
  MakeNewFn has no VmState access): a user class whose
  `__reversed__` is a Python method raises a bare TypeError
  instead of being called — the C13b class of gap. No builtin
  sequence defines `__reversed__` in its type dict (verified
  against the original sources), so builtin sequences are
  unaffected. Pinned by 3 tests (d5_reversed_list/str/print).
