§2 Mechanisms (all vendor hooks, no new Rust types)
-----------------------------------------------
Vendor spec (read from the original, gc.zig:32-43 + ADR 019):
allocations made with GC_ALLOC_FLAG_HAS_FINALISER get their
`__del__` called after marking, before sweeping, protected
(an exception is printed, not raised). Only native types use
it (files, sockets); user classes' `__del__` is never called.
Blocks allocated by a finaliser are created marked and
survive the sweep that follows. `gc_collect` (gc.zig:205-212)
is locked -> no-op, else collect -> mark -> runFinalisers ->
sweep. `gc_info` (245-270): total = used + free over the
fixed 1 MiB pool.

1. src/memory/gc.rs: (a) NEW CallCtx::alloc_with_finaliser
   next to alloc. (b) collect_inner seeds pending-finaliser
   leftovers from earlier collections into the mark phase
   BEFORE the finaliser pass, so undrained pending objects
   survive later collections instead of being swept silently.
   (c) After the sweep, the trailing run of free slots is
   truncated (slots.truncate + free-list prune) — live objects
   keep their indices, no GcRef is invalidated,
   allocated_bytes untouched (the sweep already decremented
   it). (d) Doc-header finaliser paragraph updated.
2. NEW src/runtime/finaliser.rs (105 lines):
   drain_pending_finalisers(ctx, state) — takes the pending
   list (no-op if empty); saves ctx.take_pending_raise();
   ctx.arena.lock() (no collection from inside a finaliser;
   a re-entrant gc.collect() sees the lock, returns 0, drains
   an empty list); per object in slot order:
   load_method_maybe(ctx, obj, __del__, Value::None) ->
   Ok(Some(dest)) -> call_method_n_kw(ctx, 0, 0, &dest, &[])
   (native __del__ bodies are close FunBuiltins, always the
   same call shape the vendor uses: mp_load_method_maybe +
   mp_call_function_1_protected); on Err(e) the raise is
   materialised (same convention as builtin_vm.rs) and printed
   via obj_print_exception into a String, stdout flushed,
   then written to stderr (the print_traceback shape,
   embed_exec.rs:54-68); Ok(None) -> skip; Err(_) on lookup ->
   skip silently + clear (vendor defer-restore semantics).
   After each object the pending raise is taken, then the
   object is freed. No `?` between lock/unlock, so the unlock
   always runs. The saved raise is restored at the end.
3. src/objects/containers/objfileio.rs: new_file_object gains
   a `finaliser: bool` param (flagged -> alloc_with_finaliser,
   else alloc); the open() path passes true; stdio objects
   pass false (vendor parity: file_io.zig:510-511, only
   open() uses m_malloc_with_finaliser; sockets were already
   flagged, modsocket.rs:299).
4. src/modules/modgc.rs: build_gc_module now returns
   (module, collect_fn); gc_collect_builtin itself UNCHANGED
   (still collects, returns 0 — the fallback when called
   without interception).
5. src/runtime/vm.rs: NEW VmState.gc_collect_builtin: Value,
   default Value::None (a FunBuiltin heap value never equals
   None, so the default is safe pre-registration).
6. src/runtime/vm_modules.rs: state.gc_collect_builtin =
   gc_collect right after build_gc_module.
7. src/runtime/vm_call_intercept.rs: NEW arm after the hash
   arm — fun == state.gc_collect_builtin ->
   call_gc_collect_ctx.
8. src/runtime/builtin_vm.rs: NEW call_gc_collect_ctx —
   arity (0,0) reproduced by hand via mismatch (interception
   bypasses the sig check; gc.collect(1) -> TypeError
   "argument num/types mismatch", probed identical on both);
   collect, then drain_pending_finalisers, then Ok(SmallInt 0).

Two findings that shaped the tests:
- A FunBuiltin on a user (instance) type is a staticmethod
  by the vendor's payload rule (convert_member_lookup,
  lookup.rs:149-154 — probed: a FunBuiltin __init__ on a
  user type is unbound), so the raising test's __del__ is
  called with 0 args and declares n_args (0,0). Production
  native __del__ bodies live on native types and are bound
  (1 arg); the arity reflects the lookup result, not the
  production signature.
- fun_bc_call_slot is a STUB (objfun.rs:426-434): a
  Python-level __del__ cannot run through the CallCtx-only
  drain (it would return bare PyRaise and print a spurious
  bare TypeError). Irrelevant in production: native __del__
  is always the close FunBuiltin.

  scope, record only): (a) Rust os.close(fd) only closes

  (b) Rust file write is write-through/unbuffered vs REF
  buffered: writing to /dev/full raises OSError 28 at write
  on Rust, succeeds on REF (close swallows the flush
  error) — del_raise_full.py / full_close.py.
