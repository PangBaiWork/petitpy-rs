# Brief — petitpy-rs Phase A1: qstr + grammar_data

## Goal
Port the first two frontend foundations from Zig to Rust, checked line by
line against the original. No invented behavior. This is the first code
chunk of petitpy-rs; set up the module layout the rest of the port follows.

## Sources (read them first, all of them)
- `~/workspace/petitpy-orig/src/compiler/qstr.zig` (598 lines) — string
  interning, qstr table.
- `~/workspace/petitpy-orig/src/compiler/grammar_data.zig` (1,083 lines) —
  grammar tables.
- `~/workspace/petitpy-orig/src/compiler/qstr_test.zig` — the Zig unit tests
  for qstr. These are the acceptance tests: port them to Rust, don't invent
  new ones as the bar (own probes are extra evidence only).
- `~/workspace/petitpy-orig/vendor/micropython_embed/genhdr/qstrdefs.generated.h`
  (generated by `make -C port`) — the qstr table the interner must
  reproduce, with EXACTLY the same numbering. `.mpy` compatibility depends
  on qstr ids matching, so this is load-bearing, not cosmetic.
- `~/workspace/petitpy-rs/docs/comparison-and-plan.md` — project rules.

## Procedure
1. Work in `~/workspace/petitpy-rs/` (git repo, 3 commits so far).
   Restructure the skeleton into lib + bin: `src/lib.rs` exposing modules,
   `src/main.rs` using it. Mirror the Zig layout:
   `src/compiler/qstr.rs` ← `src/compiler/qstr.zig`,
   `src/compiler/grammar_data.rs` ← `src/compiler/grammar_data.zig`.
2. Port `qstr.zig` first, then `grammar_data.zig`. Zig→Rust mapping notes:
   - Zig `error` unions → Rust `Result<T, PyError>` (see
     `src/pyerr.zig` for the `PyError!T` shape; for now a minimal
     `PyError` enum is fine — full error taxonomy comes with later phases).
   - Zig comptime tables → Rust `const` tables / `phf`-free plain
     `match` or sorted slices (pure std only, NO external crates).
   - Zig slices/allocators → Rust `Vec`/`String`/`&str`; no `unsafe`
     unless the original's semantics force it (justify each site in the
     result file; the project budget is zero new unsafe without a reason).
3. Reproduce the qstr table: extract the qstr list + numbering from
   `qstrdefs.generated.h` (or from the `make -C port` inputs) into a
   Rust table. Document HOW the table is produced (checked-in generated
   file vs build-time codegen) and why the numbering can't drift. If a
   build-time codegen step is needed, implement it as a `build.rs` that
   reads the same generated header — do NOT hand-copy ids without a
   verification step.
4. `git commit` when done (one commit for this chunk, clear message).

## Acceptance (all must hold; report every number)
- `cargo test --release --lib --tests` (or the workspace equivalent):
  ALL ported `qstr_test.zig` cases pass as Rust tests, plus table tests
  for `grammar_data` (every table entry matches the Zig source — verify
  by a dump-and-diff against the Zig tables, not by eyeballing).
- Qstr numbering: a Rust test asserts a sample of well-known qstr ids
  (at least 20, incl. the first/last and several module names) equal the
  ids in `qstrdefs.generated.h`, and the full table length matches.
- `cargo build --release` clean (warnings allowed only if pre-existing in
  the skeleton — there are none; new warnings must be fixed or justified).
- Binary size is irrelevant at this stage; no new `unsafe`; pure Rust std.
- Every `.rs` file < 800 lines.
- Write the full result (files ported, line counts, test numbers, how the
  qstr table is reproduced, anything that did NOT port cleanly and why) to
  `scripts/a1_result.txt` and report back.

## Hard constraints
- No behavior change vs the originals (there is no runtime yet — the bar
  is the ported unit tests + table identity).
- Do NOT touch `~/workspace/petitpy-orig/` (read-only reference).
- Do NOT start the lexer/parser/compiler — that's A2/A3. Stay in scope.
