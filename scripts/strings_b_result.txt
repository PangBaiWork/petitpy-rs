BRIEF CORRECTIONS (premises in scripts/strings_b_brief.md that were wrong)
---------------------------------------------------------------------------
(a) §5's premise is wrong: `str_to_int` is NOT related to `int()`; it
    is a format-internal digit scanner used only at 5 format call
    sites (objstr.zig:2565, 2584, 2802, 2913, 2920). It DOES reset
    `num` to 0 when the first byte is a digit (width/precision start
    at -1; the reset is what makes "05" parse as 5, not -95).
(b) `mp_obj_str_get_buffer` (2083-2090) was already ported by C8a —
    skipped as briefed (verified by grep before writing).
(c) Four cases ABORT the reference binary (rc=134) — Rust
    wraps/saturates/returns-self instead (intentional divergences,
    same class as C8a's):
    - `str_to_int` i32 overflow: "%9999999999d" % 1 → panic "integer
      overflow" at objstr.zig:2381. Rust wraps (wrapping arithmetic).
    - `%c` i32 cast: "%c" % (2**40) → panic "integer does not fit in
      destination type" at objstr.zig:2622. Rust truncates to u8.
    - `%*d` width cast: "%*d" % (2**40, 42) → panic "integer does
      not fit in destination type" at objstr.zig:2561. Rust wraps
      (`as i32`).
    - `center` negative width: "ab".center(-1) → panic at
      objstr.zig:2270 (@intCast i64→usize). Rust returns self.
    - `count` empty-needle start>end: "abc".count("", 5, 1) → panic
      "integer overflow" at objstr.zig:2238 (end - start pointer
      underflow). Rust saturates the slice to empty; the empty
      needle then counts the single empty position → 1 (consistent
      with count("",0,0) = 1).
(d) Method table counts are 33/35, not 32/34 as briefed: str locals
    = entries 5..38 = 33 (find..encode, including encode); bytes
    locals = entries 2..37 = 35 (hex, fromhex, decode, find..isalnum,
    no encode). Verified against objstr.zig:3536-3616.
(e) First-batch probe records for center/align cases had collapsed
    trailing/leading spaces — the repr probes are authoritative:
    "ab".center(5) = ' ab  ', center(6) = '  ab  ';
    "%+d % d" % (42,42) = '+42  42'; "%5.2d|" % 3 = '   03|',
    "%-5.2d|" % 3 = '03   |', "%5.0d|" % 0 = '    0|',
    "%*d" % (5,42) = '   42'; "é".center(4) = ' é  ' (4 chars).

KEY FINDINGS (verified by the executor, main agent to re-verify)
---------------------------------------------------------------
1. TWO `is_exact_int` definitions with DIFFERENT semantics (naming
   trap — this broke every `"{:d}"` on a small int until fixed):
   - C6's `obj::is_exact_int` = heap-only (`isExactType` semantics):
     returns FALSE for SmallInt.
   - C7's `primitives::ops::is_exact_int` = `mp_obj_is_int` (small
     int OR exact heap int) — the Zig's `objIsInt`.
   `arg_looks_integer` must use C7's (aliased `obj_is_int` in
   objstr_format.rs). The doc comment there records the distinction.
   C6/C7 lanes may want to rename one of them; not this lane's scope.
2. `mp_obj_get_int` raises TypeError "can't convert to int" for
   floats (vendor py/obj.c:306-313 — no implicit float→int
   conversion in the core language). `int_value` therefore checks
   for a heap Obj::Int FIRST (before calling obj_get_int_maybe,
   which ERRORS Overflow on an out-of-range heap int) — so
   `"%d" % (2**70)` prints all 19 digits, while `"%o" % 3.0`
   raises TypeError. C18 REQUIREMENT: the float type's IntMaybe
   slot must return NotImplemented (not convert), or this breaks.
3. `print_mp_int` prec>1 path (vendor mpprint.c:233-360, read in
   full): spaces_before = width - max(fmt_size, prec) (+ sign/
   prefix), then width = prec and the digits print zero-padded.
   Verified against the vendor source AND the reference binary
   ("%5.2d|" % 3 → '   03|').
4. `strModuloFormatImpl` flags: '0' sets PF_FLAG_PAD_AFTER_SIGN AND
   fill='0'; '#' sets a SEPARATE `alt` (not flags) — %d ignores #,
   %x/%X pass flags|alt, %o ORs SHOW_PREFIX|SHOW_OCTAL_LETTER when
   alt != 0. `nativeBase` for full builds except under %s/%r/%a
   (identity in Rust — no user classes yet, C12/C13).
5. `formatHelperInto` spec grammar: the '0' flag is NOT consumed
   where it is parsed — `str_to_int` eats it as part of the width.
   Sign flag with conv_type 's'/'c' (explicit only) → BadFormatStr,
   so "{:+}".format("ab") → "ab" but "{:+s}".format("ab") →
   BadFormatStr. Default align: numeric → '>', else '<'. The
   integer branch is entered when arg_looks_integer (bool counts) —
   hence "{:d}".format(True) → 1 but "{:s}".format(True) →
   BadFormatStr. Precision truncates BYTES ("{:.1s}".format("é") →
   first byte 0xC3). `__format__`/nativeBase are IDENTITY in Rust
   (no methods yet, C12/C13/C14 must wire them).
6. `"%*d"` negative width via `*` = NO padding (not left-adjust,
   unlike CPython); `"%.*d"` prec -1 = no precision; prec 0 does
   NOT suppress zero ("%.0d|" % 0 → "0|").
7. `"%c"`: str arg must be exactly 1 BYTE (else PctC); bytes arg is
   NOT str for %c (TypeError "integer needed"); int arg truncates
   to u8 ("%c" % 256 → \x00, "%c" % -1 → \xff).
8. `%b` is NOT supported in %-format → ValueError "bad format
   string" (probed). ure treats {n,m} as literals (RE15 finding,
   unrelated).
9. `str.format` conversion prints the arg with PRINT_STR/REPR into
   a temp str, then the spec applies to the CONVERTED str. Nested
   specs share `arg_i` (they consume args). Manual index after auto
   (or vice versa) → BadFormatStr. `"{0[0]}"` → AttrsNotSupported
   (NotImplementedError "attributes not supported") — no item
   access in format fields.
10. `bytes_decode`/`str_encode` IGNORE encoding/errors (probed:
    "ab".encode("utf-16") → b'ab'; b"\xff".decode() → raw \xff
    byte, no error). C8a's make_new likewise never validates them.
11. `str_splitlines` boundaries are ONLY \n and \r (probed: \v \f
    \x1c-\x1e \x85 U+2028 are NOT boundaries).
12. `dict_get` (objstr_b.rs) is a LINEAR scan of the stub
    MapData.entries via obj_equal with Qstr/SmallInt/Bool fast
    paths; a comparison raise is treated as "not equal". See
    "C9a re-point" — it must be replaced by C9's dict_get at
    merge time (C9a has now landed on master).

DESIGN DECISIONS
----------------
- Borrow rule (C8a's pattern): `str_data` results are copied with
  `to_vec()` before any `ctx` mutation — a borrow of the arena
  cannot outlive a `ctx` mutation.
- `Vstr::clear` frees buf but leaves alloc/len (C semantics); the
  defensive `buf.len()` check in `ensure_extra` covers a cleared
  buffer whose stale `alloc` would otherwise skip the realloc —
  invisible when Zig is correct.
- `new_str_type_from_vstr` leaves the vstr emptied with alloc = 0,
  len untouched (C semantics).
- `str_data` on a qstr immediate reads the static table; heap
  Str/Bytes read payload bytes; anything else → None (the Zig
  reads the MpObjStr layout unconditionally — UB on a non-str;
  Rust refuses instead).
- `check_is_str_or_bytes` is a no-op in the original
  (objstr.zig:681-683, mp_check_self no-op under nano + NDEBUG) —
  not ported (nothing to port).
- `format_arg_as_int` is C8b's own (separate from C7's
  `primitives::ops::arg_as_int`, which returns i64 with a different
  error type and is NOT the Zig's Obj-returning `arg_as_int` either).
- `IntValue` (I64/Big) exists because `%d` must print big ints
  (2**70 → 19 digits) while `%o`/`%x` must NOT convert floats.
- Values are always bound in `let` statements before a call taking
  `&mut fx.ctx()` (building a value and taking the call-context
  borrow in the same expression is a borrow error — hit twice).
- `str_modulo_format`'s dict-key form sets `arg_i = 1`; missing dict
  key → KeyError (not MoreArgs); end: `if (dict == NULL and
  arg_i != n_args)` → ExtraArgs. Result type = pattern's type
  (bytes in, bytes out).

DIVERGENCES FROM THE ORIGINAL (intentional, documented)
-------------------------------------------------------
- Reference-binary aborts (rc=134) → Rust wrap/saturate/return-self:
  str_to_int i32 overflow (wrap), %c i32 cast (truncate to u8),
  %*d width cast (wrap), center negative width (return self),
  count empty-needle start>end (saturate → 1). See brief
  corrections (c).
- `str.center` on a non-str fillchar → BadImplicitConversion
  (TypeError "can't convert to str implicitly"); the original
  crashes with "incorrect alignment" (mp_mirrors.zig:621).
- `"%c" % (2**40)` etc. — see above (truncate, not abort).
