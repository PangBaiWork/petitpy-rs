## §1 — What was built

E2c §4 (a) — user-class `__lt__` sorting. `VmHook` gains a third
method, `binary_op(ctx, op, lhs, rhs)` (src/objects/slots.rs):
the VM's full binary-op loop, so a FunBc `__lt__` actually
executes and the reflected fallback + `binop_unsupported` apply
exactly as at the top level. `StateHook` (vm_seams.rs) calls
`binary_op_ctx` and stashes the exception object on
`state.pending_exc` ONLY if empty — first failure wins, the
sort's run-to-completion rule. `SeamHook` (objtype/seams.rs)
delegates to the ctx-only `obj_binary_op`. The hook threads
through `list_sort` → `quicksort_range` → `sort_less`
(objlist_methods.rs), reborrowed with `as_deref_mut()` at each
level; `ListError` gains `HookRaised` (exc_name `""`, so
`record_typed` records nothing — the VM caller drains
`pending_exc` instead) and `CompareUnsupported`'s fields become
owned `String`s (a user class name is dynamic, resolved through
the pool). Both VM sort paths (`sorted`, `list.sort` — now in
src/runtime/builtin_sort.rs, see below) build the hook in a
scoped block, pin the list in `ctx.roots.extra` during the sort,
and drain `pending_exc` first on failure. `sort_less` records
the first failure only; a raising comparison surfaces the REAL
exception (ValueError "boom", list left partially sorted — the
quicksort swaps the pivot into place before the caller raises:
a 2-element list ends `[B2, B1]` on BOTH binaries, probed).
`__lt__` returning NotImplemented raises TypeError with the
class name on both sides — there is NO reflected fallback for
comparisons (the vendor has no REVERSE_LESS/MORE: the
`REVERSE_*` enum covers only OR..POWER; verified in
src/runtime/runtime.zig:700-800 + py/runtime0.h).

E2c §4 (b) — container repr dispatching user `__repr__`.
`print_helper_hook` (builtin_str.rs) mirrors `instance_print`
+ the four container prints: an instance renders through its
dunder (`__str__` for Str kind, `__repr__` for Repr — nested
instances always Repr, since container elements are always
PRINT_REPR in the Zig); list/tuple/dict/set recurse elements
with Repr (dict keys AND values; `OrderedDict({...})` for
ordered dicts; single-tuple comma; `set()`/`frozenset()` for
empty sets); anything else delegates to `obj_print_helper`.
SLOT SEMANTICS: a dunder raise inside a container is SWALLOWED
and the default rendering is used — the reference ABORTS here
(rc=134, null-pointer panic at mp_mirrors.zig:745), so Rust
keeping the fallback is a documented divergence (same class as
the other abort-vs-fallback cases). Only the top-level
`str`/`repr`/`print` of an instance propagates a raise
(existing behaviour, unchanged). Wired into `call_str_ctx` /
`call_repr_ctx` (container branch before the type-call
delegation) and `call_print_ctx`'s render closure (the gate now
also fires when an arg is a container). No GC pinning is needed
here: call args are rooted by the frame-roots snapshot
(`sync_frame_roots` — nested frames append after the outer
roots), unlike `sort_items_with_key`'s fresh decorated pairs.
A namedtuple is an `Obj::Tuple` headed by its class — the
container check requires an EXACT tuple, so `repr(E())` and
`repr([E()])` stay `TupEmpty()` via the class's own print slot.

E2c §4 (c) — reflected fallback at internal callers.
`obj_equal_not_equal` (obj_ops.rs): when the VM passes its hook
and both operands are exact lists or exact tuples, compare
element-wise through the hook (recursive EQUAL dispatch,
bool-ified like `obj_equal`); length mismatch decides
immediately. The ctx-only path (`call` is None) keeps the
generic loop exactly as before; tuple-vs-list and subclasses
fall through. `binary_op_ctx` (vm_rt.rs): after the
IN→CONTAINS swap and before the generic loop, same-kind
list/tuple ordering (Less/More/LessEqual/MoreEqual) runs
`container_compare`, a line-for-line mirror of `seq_cmp_objs`
(swap Less→More, element equality via the EQUAL dispatch,
ordering result counted only when exactly `Bool(true)`,
length tie-breaks). `obj_binary_op` / `obj_unary_op`
themselves need NO signature change; `seq_cmp_objs` stays as
the ctx-only fallback. Consequence pinned by test: ordering
needs BOTH `__lt__` and `__gt__` — an `__lt__`-only class's
`(A(1),) < (A(2),)` raises `TypeError ... for __gt__` (the
swapped op), on both binaries.

Type-name fix (feeds all three items): new `obj_type_name`
(obj_ops.rs) resolves heap type names through the pool, so a
user class reads `'A'` instead of `''`. Used by
`binop_unsupported` (vm_rt.rs) and sort_less's
`CompareUnsupported`. `max([A(3), A(1)])` now raises
`... for __gt__: 'A', 'A'` on both binaries (was `''`, `''`).

Split (file-size rule): `builtin_vm.rs` hit 802 lines, so the
sort family (`call_sorted_ctx`, `sort_items_with_key`,
`sort_with_key`, `call_list_sort_ctx` — 238 lines) moved
verbatim to NEW src/runtime/builtin_sort.rs (273 lines);
builtin_vm.rs is now 563. `kw_args` / `mismatch` are
`pub(crate)` in builtin_vm.rs; the interception chain
(vm_call_intercept.rs) now calls `builtin_sort::…`.
`is_ordered_dict_value` is `pub(crate)` in objdict.rs (used by
`print_helper_hook`).

Tests: NEW src/runtime/vm_tests_e2d.rs (9 tests, Fx harness):
sort user `__lt__` (list.sort + sorted + reverse + key+lt),
sort raising ValueError (partial sort + real exception),
sort `__lt__` → NotImplemented (TypeError with `'B'` names),
container ordering + equality (incl. the `__gt__` swap pin),
container repr (nested, dict key/value, set, tuple, str/repr),
namedtuple-in-list, raising-`__repr__` fallback shape,
max() TypeError names.

- 10 probe groups, all byte-identical (stdout+stderr+rc)
  except p6 (the documented abort-vs-fallback divergence):
  p1 sort `__lt__`/`__repr__`, p2 container repr, p3
  NotImplemented sort, p4 raising comparison, p5 nested
  containers + set + dict, p6 raising `__repr__` in a list
  (ref ABORTS rc=134 with the mp_mirrors.zig:745 panic
  trace; Rust prints `[<R object at 23f>]` and continues),
  p7 (same class as p6), p8 tuple/list ordering + max names,
  p9 sort(key=) + user `__lt__`, p10 tuple/list equality
  (incl. nested `[[A(1)]] == [[A(1)]]`).
- Extra probes: `<=`/`>=` on tuples/lists (identical);
  `[E()]` → `[TupEmpty()]` (identical); set order
  `{A(1), A(2)}` + `frozenset({A1, A2})` identical, but the
  3-element set `{A(1), A(2), A(3)}` differs — see §4.
- Defects caught in-lane (all fixed before the final run):
  (1) `print_helper_hook` first took ANY `Obj::Tuple` as a
  container — broke `e2_namedtuple_empty_repr`
  (`repr(E())` became `"()"`); fixed with the exact-tuple
  requirement. (2) Three borrow errors: `sort_less` moved
  the hook before reading `hook.is_some()` (read the flag
  first); `quicksort_range`'s hook param needed `mut` for
  `as_deref_mut()`; the `drop(hook)` after `collect_iterable`
  extended the borrow past the `map_err` closure — the hook
  now lives in a block that ends after the collect.
  (3) `container_compare` first used `exc_from_typed` on a
  `PyError` — wrong converter (`TypedRaise` bound);
  `exc_from_pyerror` is the PyError converter.
  (4) `set_items` is privately imported by objset.rs — import
  it from `map_set` directly.
  (5) Two test scripts had a stray leading space before
  `except` (SyntaxError); one asserted `'[B1, B2]'` after a
  failed sort where both binaries leave `'[B2, B1]'`.
- No new `#[ignore]`d tests; the frozen-deque ignored test
  is untouched (E2f's scope).
