§4 — FINDINGS (all probed on the reference binary, C17)
------------------------------------------------------------------------
  - int("010") == 10 (explicit base 10); int("010", 0) → ValueError
    "invalid syntax for integer" (base-0 → base 1, no digits).
  - int("_") == 0; int("1_000") == 1000; int("0b102") /
    int("12z") → ValueError "invalid syntax for integer".
  - float("inf"/"infinity"/"nan"/"1_0.5"/" 1.5 ") == inf/inf/nan/
    10.5/1.5; float("1e+") / float("1e") / float("1.5j") /
    float("j") / float("3+4j") → ValueError "invalid syntax for number".
  - EVERY complex literal raises at LOAD time: print(1j),
    print(3+4j), print(1e-2j), print(1.5j) → ValueError "invalid
    syntax for number". Cause (proven by .mpy bytes): the compiler
    emits `1j` as a FLOAT const `"1j"` (Rust and Zig byte-identical)
    and `3+4j` as int 3 + FLOAT `"4j"`; the loader calls
    mp_parse_num_float(allow_imag=false), which rejects the 'j'.
    The Rust loader used to return 0.0 — now raises, matching.
  - A hand-built .mpy with a COMPLEX entry "1j" parses fine
    (Complex{0,1}) but the module then crashes in libc (the
    original's complex objects are broken at runtime — pre-existing,
    C18's slot work, not the parse). A COMPLEX entry "(1+2j)"
    (the vendor PRINT_REPR form, objcomplex.c:45-62) raises
    ValueError — the parenthesised text can never load, because
    the loader calls mp_parse_num_float (force_complex=false).
    Same for "3+4j" as a COMPLEX entry. Only bare "Nj" loads.
  - "3 + 4j" fails even for parse_num_complex: whitespace is
    skipped BEFORE the sign but NOT between sign and digits, so
    the second pass sees " 4j" after '+' and consumes nothing
    (probed: COMPLEX .mpy entry "3 + 4j" → ValueError). My first
    test expected success — the probe corrected it.
  - Two test-only failures during the lane, both fixed in-lane:
    (a) the "3+4j " (trailing space) case is VALID (trailing
    whitespace is skipped before the end check) — moved to the
    success table; (b) the "3 + 4j" case above.
