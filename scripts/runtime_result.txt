Intentional divergences / verbatim quirks (all probed)
------------------------------------------------------
- DIVMOD mistag (p8): divmod(-(2**62),-1)[0] is -2**62, not 2**62 —
  the Zig's DIVMOD arm uses raw newSmallInt; // alone is correct.
  Rust: wrap_small_int on both DIVMOD results (no-op in-window).
- Unary small-int else is INVERT for ANY unlisted op (Zig
  `// assert(op == MP_UNARY_OP_INVERT)`): mp_unary_op(LEN, 5) == -6.
  The `len(5)` -> "object has no len" error comes from the len
  builtin's own mp_obj_len_maybe check, not mp_unary_op.
- `1 in 2` raises binopUnsupported with an EMPTY op name: the
  small-int chain (both-small-int only) catches IN before the
  IN->CONTAINS swap.
- NotIn / IsNot are never emitted (emitter lowers `not in` / `is
  not` to `in`/`is` + `not`); calling binary_op(NotIn/IsNot)
  directly raises binopUnsupported, exactly like the Zig.
- `8 % -3 == -1`, `8 // -3 == -3`, `-8 // 3 == -3` (floored, Zig
  @mod/@divFloor — NOT Euclidean rem_euclid/div_euclid).
- `1 << 62` is a HEAP int 2**62 (go_big: 1 > SMALL_INT_MAX >> 62).
- load_global checks globals FIRST, then override_dict, then
  builtins globals (runtime.zig:301-325) — the override only
  fills a miss.
- Bound-method call prepends self (args[1] rule): a 0-arg fn
  called bound is an arg-count mismatch in the original too.
- unpack_sequence / unpack_ex return items in NATURAL order; the
  Zig's items array is reversed (VM stack-layout detail).

Cross-lane fixes made by this lane (verified against the original)
-------------------------------------------------------------------
1. load_method_maybe used MapData::find_qstr on the type's dict —
   find_qstr is the COMPACT path and panics (index out of bounds)
   on FIXED ordered ROM dicts (new_fixed, empty index). Re-pointed
   at the general dict_lookup_qstr. (object_locals_dict lookups
   hit this in 3 tests.)
2. C12b's is_exception_type returned TRUE for exception INSTANCES
   (header-type fallback). The Zig (objexcept.zig:104-111) falls
   through to mp_obj_is_subclass_fast, which is false for a
   non-type — probed (p9): `except ValueError("b")` raises
   binopUnsupported, and make_raise_obj must NOT call an instance.
   Fixed the non-Type arm to false in objexcept.rs. C12b's test
   (objtype_tests.rs:551) does not pin the instance case.
3. RuntimeSeams fields are now owned Box<dyn FnMut> (not &mut dyn):
   a &mut to a bare-fn stub is a reference to a temporary and
   cannot leave the stub() constructor (E0515). stub() works
   unchanged at call sites.

Deviations from the brief (documented, justified)
-------------------------------------------------
- load_method_maybe returns Result<Option<MethodDest>, RtError>,
  not bare Option (the Zig's B2 comment requires the pending-exc
  propagate; an attr-slot raise must not become "no attribute").
- call_prepare_args_n_kw_var takes starred: &[Value] (the objects
  to expand), not a count — the count cannot express which objects.
- mp_load_method_maybe's attr-slot Ok(None) is the SENTINEL
  fall-through to the locals-dict lookup (re-read runtime.zig:
  1195-1231: `if (dest[1] != SENTINEL) return; dest[1] = 0;`
  then locals_dict), not a short-circuit.
- mp_import_name takes (name, fromlist, level); globals come from
  thread state inside (runtime.zig:1468 builds the 5-arg array
  internally) — the brief's earlier 5-field sketch was wrong.
- load_method_protected swallows RtError::PyRaise as well as
  AttributeError from the attr call (corpus builtin_getattr.py
  requires it: getattr(b, "b", "default") with a raising
  __getattr__); a non-AttributeError raise arriving as bare
  PyRaise is swallowed here — documented gap, closable when the
  slot boundary carries the kind (C13 pending_exc).
- RuntimeSeams is Box-based (see cross-lane fix 3).

---------------------------

   through the call slot until C13's pending_exc — a user iterator's

   generator path are unaffected). Same root cause hits mp_resume's
   __next__/send branches and next(it, default) on a user iterator.
2. The getitem seam can never return Stop through a real
   __getitem__ call until C13 (any error -> Raise), so
   __getitem__-protocol iteration ends with an error instead of
   cleanly at exhaustion — same root cause.
3. f(*"ab") star-expansion cannot run end to end yet: the tree's

   and C11's iternext has no str-iterator tag (new_str_iterator
   builds extra: vec![]). The getiter expansion path itself IS
   tested (f(*{"a":1,"b":2}) expands keys via dict getiter).
4. mp_load_method_protected swallows bare PyRaise (see above).
5. The C11 `call` seam degrades OutOfMemory to Raise (the seam
   type has no OOM outcome); IterError::IndexError degrades to
   RtError::PyRaise (no IndexError variant in RtError).
6. import_from's submodule fallback needs the dotted name
   pre-interned (the InternFn seam is find-only in tests).
7. The module type's attr slot (module_attr) is wired only in the

   wiring (D1's module setup) must set attr: Some(module_attr).
8. mp_init/mp_deinit out of scope; typingCall's typing import goes
   through the ImportSeam (fails until C15/D).
