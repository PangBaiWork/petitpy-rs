§3 — Rust-side adaptations (with file:line pointers)
----------------------------------------------------
(a) Per-interpreter Vm (no save/load ported) — src/entry/api.rs:130-145
    (Interp), :1038-1091 (ppy_new). Each `ppy_interp` owns its own
    `Box<Vm>` (own arena, qstr pool, code store, modules, globals).
    Verified by reading `Vm::new` (src/runtime/vm.rs:392): all state is
    per-Vm; the only process-wide mutables in the tree are modsocket.rs'
    sockets table (OnceLock<Mutex<HashMap>>, OS-level) and modtime.rs'
    MONO_EPOCH (immutable after init). The Zig's `save`/`load`/`switchTo`
    and `globals` list are NOT ported. `ppy_new` registers `__main__`
    with an empty `run_main_source(b"", "<stdin>", None)` and keeps its
    globals dict as `main_globals`; `set_sys_path`/`set_sys_argv` replace
    (no PYTHONPATH / PETITPY_LIB wiring — sys.path holds ONLY the config).
(b) Reentrant lock — src/entry/api.rs:176-235. `std::Mutex` is NOT
    recursive, so reentrancy is `PROCESS_LOCK: Mutex<()>` +
    `LOCK_OWNER: AtomicU64` + `LOCK_DEPTH: AtomicUsize` + a thread-local
    `MutexGuard<'static, ()>` held by the outermost entry. Same-thread
    reentry (a host function calling the API) bumps the depth and skips
    the mutex; other threads block. The thread id is NOT
    `ThreadId::as_u64` (unstable, #67939): each thread takes the next
    number from `NEXT_THREAD_NUM` on first use (0 = never assigned =
    lock free). The header's deadlock note is preserved in the module
    docs. `LOCK_GUARD`'s `'static` is sound: the mutex is a `static`
    and the guard is only dropped by the thread that took it.
    Interpreter slots: `INTERP_BITS: AtomicU64` bitmask, no second mutex.
(c) Handle roots — src/memory/gc.rs:31-56 (RootSet.handles) + :172-179
    (iter). The handle table IS `RootSet.handles: Vec<Option<Value>>`
    (slot 0 kept `None`, never handed out) — `RootSet::iter()` chains
    it, so `collect_inner` marks handle values. A separate leg from
    `extra` because `rebuild_frame_roots` truncates `extra` to
    `extra_base` on generator suspend/resume, which would drop handle
    roots. `new_handle` (api.rs:296) scans for the first free slot (no
    explicit free list — same observable behavior: freed slots reused,
    slot 0 never handed out). Tag = interp index << 26 (`SLOT_BITS`).
    Verified by the stress runs (§1) + the Rust test
    `handles_survive_gc_stress` (api_tests.rs).
(d) Print sink — src/support/output.rs:40-100 (thread-local `CSink` +
    `set_thread_sink` / `write_sink`), wired into
    `src/objects/containers/objfileio.rs:147-176` (fileio_write Stdout /
    Stderr arms) and `src/objects/strings/mpprint.rs:652-672`
    (`MP_PLAT_PRINT_SINK_AWARE`, used by `print_impl_with`'s no-file
    path in src/runtime/vm_builtins.rs:187). NOT a `VmState` field (the
    output.rs doc's suggestion): the write sites are ctx-only and cannot
    see `VmState`; the Zig keeps `output.sink` as a process-wide global
    saved/restored per interpreter, and the Rust form is a thread-local
    installed by the API bracket's `SinkGuard` (api.rs:256) and restored
    on exit. `__repl_print__` keeps plain `MP_PLAT_PRINT` (the REPL
    never runs under embedding). Verified by api_test's output-capture
    checks (exact 8-write sequence, per-interpreter sinks).
(e) Host functions — src/runtime/vm.rs:135-144 (`VmState.host_call_builtin`),
    src/runtime/vm_builtins_bind.rs:243-268 (creation in `build_builtins`,
    name `"__ppy_host_call__"` via `pool.from_strn`, sig (1,255),
    `intercepted_stub_fn`), src/runtime/vm_call_intercept.rs:197-208
    (GcRef-identity arm -> `entry::api::call_host_ctx`, api.rs:560-620).
    ONE shared `FunBuiltin`; the bound method's `self` is the host index.
    `call_host_ctx` validates args[0], builds TEMPORARY handles for
    args[1..], releases them before returning, takes the exception from
    `interp.err` on non-OK else `RuntimeError("host function failed")`,
    result 0 -> `None`. n_kw > 0 -> `TypeError("argument num/types
    mismatch")` (mirrors `call_fun_builtin`'s arg check for a kw-less
    var builtin); kwargs are otherwise ignored like the Zig's hostCall
    (argc = n_args - 1).
(f) eval_exec_named — src/runtime/vm_eval.rs:117-208 (`eval_exec`
    delegates with `"<string>"`). `ppy_exec` must compile with the
    host-given filename so tracebacks name it — api_test's
    `format_exception` check pins `File "<test>"` (two frames).
(g) `ppy_new` calls `vm.arena.gc_init()` (api.rs:1056) — see §4(h).
(h) `ppy_type_name` (api.rs:1545) locks + enters directly (no produce),
    resolves via `obj_type_name`, and caches a `CString` per NAME
    string in `interp.type_names` (keyed by name, not by type GcRef —
    a GcRef key could go stale if the type were collected and its slot
    reused; the name string is the value). NULL for a bad handle or a
    name with an interior NUL.
(i) `ppy_to_int` (api.rs:1406): `obj_get_int_maybe` — Ok(Some) -> value;
    Ok(None) -> `TypeError("expected an int")` (explicit, NOT

(j) `ppy_to_str` / `ppy_to_bytes` (api.rs:442-480, `data_ptr_body`):

(k) `ppy_raise` (api.rs:1797): type looked up in the builtins module

§4 — Left open, unsafe audit, header-vs-code disagreements, seams
------------------------------------------------------------------
LEFT OPEN (all pre-existing or explicitly out of scope; none blocks the
brief's acceptance):
(a) Host-function kwargs are ignored (n_kw > 0 is rejected; a host
    called WITH kwargs from Python raises "argument num/types mismatch"
    — the Zig's hostCall computes argc = n_args - 1 and ignores kwargs,
    but no api_test case covers kwargs; untested edge, noted here).
(b) REENTRANCY CAVEAT (documented in api.rs module docs): a nested
    `ppy_*` call from a host function creates a second `&mut` path to
    the same `Vm`/`Interp` through the raw `*mut Interp` while the
    outer call's `&mut` borrow is suspended. Sequential, lock-
    serialized, outer borrow never used while a nested call is active —
    the same guarantee the Zig relies on via process-wide globals. The
    alternative (restructuring the VM to UnsafeCell interior mutability)
    is out of scope and forbidden by the brief.
(c) `modsocket.rs`'s process-wide sockets table (OnceLock<Mutex<HashMap>>)
    is OS-level state shared across interpreters, same shape as the
    original (its sockets table is also global). Not touched.
(d) `new_handle` uses a free-slot scan instead of the Zig's explicit
    free list — same observable behavior (freed slots reused, slot 0
    never handed out); the scan is O(slots) per allocation, fine at
    embedding scale (api_test's 100-handle garbage loop passes).
(e) `ppy_getitem`/`ppy_setitem` on USER instances (the
    `try_instance_subscr` path) is not covered by api_test (it uses
    dict/list only) — the path is the dispatch's shape, but no C or
    Rust test exercises a user `__getitem__` through the API.
(f) `ppy_exec`'s filename is converted with `from_utf8_lossy` (the Zig
    passes raw bytes as the source name; Rust's compiler needs `&str`).
    Non-UTF-8 filenames lose bytes in tracebacks — untested edge.
(g) Defensive NULL handling BEYOND the Zig (documented divergence):
    NULL `py` -> PPY_ERROR / NULL / no-op; NULL out-pointers ->
    PPY_ERROR; NULL `config` strings -> empty; NULL `argv`/`items`
    with n > 0 -> PPY_ERROR. The Zig would fault on these. api_test
    never passes NULL.
(h) `Vm::new` does NOT call `arena.gc_init()` — `NPY_GC_STRESS` was
    dead on EVERY path (CLI included) until this lane: `ppy_new` calls
    `vm.arena.gc_init()` so the stress run is meaningful through the
    library. The CLI path still never calls it (pre-existing tree gap,
    out of this lane's scope — noted, not fixed, because the brief
    forbids touching the CLI).
(i) `ppy_str`/`ppy_repr` use `obj_print_helper` (the Zig's
    `mp_obj_print_helper`) — for an instance with a raising `__str__` /
    `__repr__`, the ctx-only print path's behavior is the tree's
    existing one (E2d's hook lives in the VM dispatch, not in
    `obj_print_helper`); api_test only prints tuples/lists/dicts.

HEADER-VS-CODE DISAGREEMENTS (code wins, per the brief — each noted):
(1) `ppy_exec`'s signature: the lane plan assumed (filename first,
    with a result out-param); the header AND api.zig say
    `ppy_exec(py, src, len, filename)` with NO result. The code won;
    the plan was wrong (api.rs:1113).
(2) `ppy_to_int` OverflowError: header ("an int that does not fit a
    machine word raises OverflowError") and code agree — the vendor
    `mp_obj_get_int_maybe` raises it itself; `raise()` does not
    overwrite a pending exception. No disagreement in behavior, but
    the implementation MUST route Err(Overflow) through
    `exc_from_obj_error` and Ok(None) through an explicit "expected an
    int" TypeError — the two messages are different code paths.
(3) `ppy_fetch_error`'s `fetched` dance (api.zig `takeError`): needed
    in the Zig because `run` clears `py.err` on entry; unnecessary in
    Rust — `new_handle` allocates no arena memory, so the error is
    taken directly from `interp.err` (api.rs:1836).
(4) `NPY_GC_STRESS`: the brief said "the Rust GC already reads
    NPY_GC_STRESS (gc.rs:414-418)" — true of `gc_init`, but `Vm::new`
    never calls `gc_init`, so the env var was dead on every path.
    `ppy_new` now calls it (see (g) above). The stress runs in §1
    would have passed trivially WITHOUT this fix (no collections at
    all); with it they actually exercise the handle roots.
(5) `ppy_type_name`: header says the result is "possibly an interned
    string of that interpreter" — the Rust pool bytes are NOT
    NUL-terminated, so a `CString` copy per name is required (cached in
    `interp.type_names`); the pointer stays valid for the interp's
    lifetime, as the header promises.
(6) `ppy_new`'s config: header allows NULL config; the Zig reads
    `config->path` unconditionally when non-NULL — Rust copies the
    arrays into `String`s (sys.path / sys.argv are `Vec<String>`), so
    non-UTF-8 entries are lossy-converted (same caveat as (f)).
