Lane: lane/h-subprocess, worktree ~/workspace/petitpy-rs-h-subprocess, baseline d316394.
Brief: scripts/h_subprocess_brief.md (master checkout).
User instruction (overrides agent-rules "对照原文" for this module only):

§1 — 改了什么
-----------
- src/modules/modsubprocess.rs（唯一改的源码文件；796 → 744 行）：
  - 删 U5：超时 kill 的 `unsafe-ffi` SIGTERM + 1.0s grace 路径。两构建一律
    `Child::kill()`（SIGKILL，无 grace），超时 returncode 一律 -9。
    （std 里没有 SIGTERM；CPython `Popen.kill()` 也是 SIGKILL。）
  - 删 U8：`pre_exec` dup2 的 feature 路径 + `CommandExt` import。
    fd 流模式改走 `fd_stdio()`：`BorrowedFd::borrow_raw(fd)` +
    `try_clone_to_owned()` → `File::from(OwnedFd)` → `Stdio::from(File)`。
    dup 共享原 fd 的 offset/append，socket fd 可进 stdio；解析不到的 fd
    → dup 失败 `EBADF` → `OSError(9)`。`stderr=STDOUT` + `stdout=fd`
    时对 stdout fd 再 dup 一次（两 child fd 指向同一 open file
    description，写顺序交错）。
  - 模块头文档：U5/U8 分歧列表换成统一行为说明。
  - 只改这一个文件。没碰 modsocket.rs / modselect.rs / frozen 包。
- src/modules/modsubprocess_tests.rs：
  - `subprocess_timeout`：删 cfg 分支，两构建都断言 -9。
  - `subprocess_timeout_sigterm_grace`（feature-only，测已删行为）删掉，
    改为两构建都跑的 `subprocess_timeout_sigterm_ignored`：trap 掉
    SIGTERM 的子进程超时后 -9，且整次调用 < 1.0s（钉死"无 grace"；
    旧 feature 构建要先等 1.0s grace，总耗时 > 1.2s）。
  - 4 个 fd 测试去 feature 门（`subprocess_fd_shared_offset` /
    `subprocess_fd_append` / `subprocess_fd_socket` /
    `subprocess_fd_stderr_stdout`），两构建都跑。
- tests/h_subprocess.rs（新增，跑在 petitpy 二进制上，8 个探针）：
  - `h_fd_stdin_stream`：stream fd 作 stdin，子进程读到数据。
  - `h_fd_stdout_file`：`os.open` 的 fd 作 stdout，输出落文件。
  - `h_fd_stdout_shared_offset`：父进程先写 "AAA"，子进程接续写
    "BBB" → 文件 "AAABBB\n"（dup 共享 offset 的证明）。
  - `h_fd_socket`：socket fd 作 stdout，数据从对端出来。
  - `h_timeout`：`timeout=0.2` 跑 `sleep 10` → `(-9, None, None, True)`。
  - `h_spawn_fail`：不存在的命令 → 127。
  - `h_fd_bad`：fd 9999 → `OSError: [Errno 9] EBADF`，exit 1。
  - `h_frozen_subprocess`：经 frozen `subprocess.py`：`run` +
    `capture_output`、`call`、`check_output`、`check=True` →
    `CalledProcessError`、`timeout` → `TimeoutExpired`、file 对象
    作 stdout（`fileno()` 走 fd 模式）。
  - 探针注：`Command` 在 exec 时会关掉除 stdio 外的所有 fd，所以
    Rust 侧的 fd 是以 petitpy 自身 stdio（fd 0）传进去的，脚本里用
    0 号 fd；文件 fd 则在脚本内经 `os.open` 取得（真实端到端路径）。

§4 — 已知遗留
--------------
1. 超时 returncode 一律 -9（原 feature 构建是 -15，有意统一，见 brief）。
2. fd 解析不到报 `OSError(EBADF)`（全平台统一，文档注明）。
3. `Popen` 仍不支持（frozen `subprocess.py` 层面，本 lane 不动）。
4. brief 前提偏差——主 agent 已决定：接受。`BorrowedFd::borrow_raw`
   在 std 里是 `unsafe fn`，所以 `src/modules/modsubprocess.rs`
   里有且仅有 1 个 `unsafe` 块（第 260 行，dup 表达式，不变量写
   在 `fd_stdio` 文档里；无 FFI、无 C）。主 agent 的理由：从
   BuiltinFn（只有 CallCtx，拿不到 VmState/fd 表）把 fd int 转成
   安全对象的唯一办法就是它；拦截版要碰 4 个文件（含并行的
   H-socket 的 modsocket.rs），代价不成比例；该块是 sound 的
   （立即 dup、坏 fd 走 EBADF 错误、不变量已写在文档里），且无
   FFI、无 C，符合"纯 Rust"。验收标准改成：modsubprocess.rs
   允许且仅允许这 1 个 unsafe 块（std-only，带不变量注释）。
   （原 brief 的"全 safe"与"grep unsafe 为空"不能同时满足——
   要做到全 safe 只能走拦截模式：`VmState` 加字段 +
   `vm_call_intercept.rs` 加分支 + `modsocket.rs` 加 `pub(crate)`
   dup 助手。）
5. Windows fd 模式：合成 fd 只在 `state.os_fds` 里，`FunBuiltin`
   看不到，所以 Windows 上除 0/1/2（dup std handle）外一律
   `EBADF`。Windows 的 fd 模式此前也从未工作过（`/proc` 重开
   报 ENOENT）。主 agent 已确认：记在 §4 即可，不是回归。
6. `sys_kill` / `sys_dup2` / `SIGTERM` / `SIGKILL`
   （`src/support/ffi.rs`）在本 lane 后已无任何调用方
   （grep 确认；原先唯一的调用方就是本模块的 U5/U8）。
   它们是 `pub` 项所以不产生 dead-code 警告。主 agent：先不动
   （H-socket 可能还在用），清理以后再定。
7. 基线 lib 数与 brief 不符（非本 lane 回归，见 §2）：brief 的
   "1739/1755"是 d1770f2 的数；d316394 基线默认构建是 1729/10/1，
   feature 构建全套跑不完（g0 select / os fd 区的 IO Safety
   abort）。本 lane 默认 +5、feature 到 abort 点前与基线完全
   一致，0 新失败。主 agent 验证时会看到同样的基线状态。
8. （无其他遗留。超时 -9、fd EBADF、Popen 不支持见上 1–3 项。）
