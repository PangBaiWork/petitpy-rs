Layouts (IteratorData source/index/extra)
-------------------------------------------
- map: source=fun, extra=[110, it1, ...]
- filter: source=fun-or-None, extra=[111, iter]
- enumerate: source=iter, extra=[112, cur: Value] (cur is a Value::int —
  heap Int out of the 62-bit window, per the C9c precedent)
- zip: source=None, extra=[113, it1, ...]
- reversed: source=seq, index=cur_index, extra=[114]
- getitemiter: source=obj, index=next index, extra=[115]
- deque-it: source=deque, index=cur (ring position), extra=[116];
  reads the deque payload live each step (matches the
  appendleft-between-next probe)

Dispatch collision (len==2 extra): a range iterator stores [stop, step]
with no tag, and map-1/filter/zip-1/enumerate also have two extra
entries; a range's stop can numerically equal a tag (range(110,115)).
Resolution by shape: extra[1] is an Obj::Iterator -> map-1/filter/zip-1
(dispatch by tag); otherwise extra[1] is an int -> range (source is
Obj::Range) or enumerate (extra[0]==112, source is the sub-iterator).
Dict views (extra empty) -> "object not an iterator" from iternext.

Seams (local, C13 consumes — same pattern as C10's local runner seam)
----------------------------------------------------------------------
- CallOutcome { Value(Value), Stop, Raise } — outcome of a VM call made
  on behalf of iterator machinery. Stop = callee raised StopIteration
  or IndexError; Raise = anything else. map/filter treat both Stop and
  Raise as Err(PyRaise) (the Zig propagates a func raise as an error,
  never as end-of-iteration); only the getitem iterator treats Stop as
  end-of-iteration.
- IterSeams<'a> { call, getitem }: `call` calls a function value (map
  func, filter predicate, reversed's `__reversed__` method with the
  object passed as its first argument — the bound call); `getitem` calls
  obj.__getitem__(index) with Stop/Index classification. The getitem
  seam is a separate closure because the bound `__getitem__` method
  value cannot be produced without C12's method lookup; its contract is
  exactly the Zig's mp_call_method_n_kw([__getitem__ method, obj, index])
  + excIsStopOrIndex classification, packaged as one operation.
- InternFn<'a> = &'a mut dyn FnMut(&[u8]) -> PyResult<u32> — the
  interning seam: qstr_from_strn needs &mut RuntimeQstr, but CallCtx.pool
  is a shared &. The named-tuple factory (and make_new, for heap-Str kw
  keys) takes the interning closure as a parameter; the VM (which owns
  the pool mutably) supplies it. In tests the fixture pre-interns the
  names and the seam is a find_strn lookup over the (shared) pool,
  panicking on a miss (test bug).
- getiter(ctx, value) -> PyResult<Value> (local, iters module):
  (1) Obj::Iterator -> as-is; (2) type flags & 0x0080 -> as-is;
  (3) type.getiter Some -> call it (Err(PyRaise) falls through per the
  C6 convention); (4) type.subscr Some -> build a getitem iterator (the
  Zig loads `__getitem__` as a method; the Rust interim routes through
  the subscr slot — see divergences); (5) else "object not iterable".
- iternext(ctx, it, seams) -> PyResult<Option<Value>>: Ok(Some(v)) =
  next item, Ok(None) = StopIteration, Err(PyRaise) = the iterator
  raised. Dispatches on the IteratorData tag. Non-Iterator values ->
  PyRaise "object not an iterator" (user iterators with `__next__`
  are C12's method machinery — documented gap).

Intentional divergences (original aborts or is undefined; Rust raises/returns)
------------------------------------------------------------------------------
- deque([], 2**62): original ABORTS rc=134 (objdeque.zig:96 overflow);
  Rust returns OutOfMemory (try_reserve_exact failure).
- getitemiter method load is LAZY (at each next step through the getitem
  seam); the Zig loads `__getitem__` EAGERLY at getiter time and stores
  the bound method. C13 may hoist the load into getiter once method
  lookup exists.
- str iteration goes through the getitem fallback (subscr slot), not the
  Zig's dedicated str iterator (objstr.zig:3662); observably identical
  (same values, same 'iterator' type name) except the construction path.
- enumerate counter out of the 62-bit window: the Zig's `newSmallInt`
  is a raw shift with no window check (address-dependent garbage);
  Rust keeps the true value as a heap Int.
- deque make_new/extend use `collect_iterable` (the C9 tuple/dict
  pattern), NOT the streaming mp_iternext loop: (1) an infinite iterable
  with the overflow flag would hang here where the Zig raises "full"
  after maxlen+1 appends; (2) C11 iterators (map/filter/...) are not
  `collect_iterable` shapes — deque(map(...), n) reports "object not
  iterable", the same limitation tuple/dict already have; the general
  protocol is C13's.
- reversed(dict) KeyError payload dropped at the slot boundary (C6
  convention); the test asserts the raise, not the payload.
- ADD still diverges: the Zig uses subclass-fast (namedtuple IS a tuple
  subclass, a+(3,) works), Rust requires an exact tuple — C12 must
  relax it (already recorded by C9c).

Sig-error model (polled, C9b precedent)
----------------------------------------
map/filter/zip/deque sig checks are POLLED: record the sig error,
proceed, a later error (getiter/extend) overwrites it, return the sig
error at the end if nothing overwrote it. map(str)/map()/filter 1-or-3
args/zip kwargs/deque 0-1 args or 4+ args or kwargs -> mismatch;
map(str,[1],5)/filter(str,5)/zip([1],5)/deque(5) -> "object not
iterable" (construction-time getiter/extend error wins).
- map/zip getiter ONLY the positionals (the Zig loops args[0..n_args]);
  keyword pairs are never getiter'd (a kw key is a qstr — getiter'ing it
  would spuriously fail in the fixture, where str has no getiter slot).
- deque reads maxlen/flags only from real positional slots (n_pos =
  args.len() - 2*n_kw); with < 2 positionals the Zig's args[1] read lands
  on a kw key/past the end — unobservable, the sig error is raised.
- enumerate parse is NOT polled (the Zig returns NULL as soon as the
  parse sets pending_exc) — a bad start fails before getiter.

Reversed `__reversed__` lookup (interim)
------------------------------------------
Reads the operand type's dict for a `"__reversed__"` entry (id via
ctx.pool.find_strn(b"__reversed__"); 0 -> skip). Instance-dict lookup
is C12's. Bound call passes the object as the method's first argument
through the call seam. Sig-error interaction: method found + call
success + sig_err -> mismatch (result discarded); call failure -> that
error wins.
Reversed iternext calls the subscr slot DIRECTLY (not via call_subscr,
which erases raise-vs-not-implemented): slot None ->
ObjError::NotSubscriptable ("object isn't subscriptable"); slot
Err(PyRaise) -> PyRaise (e.g. dict KeyError, payload dropped per C6).
Cursor decremented BEFORE the subscript (the Zig's order — a raising
subscript leaves the iterator advanced).

Known gaps (fixture limitations, NOT fake-done)
------------------------------------------------
- The fixture's plain str type carries no LEN/subscr/getiter slots (the
  production str type, C8a, does), so three reference-probed behaviours
  are NOT exercised in Rust tests: filter(None, [..., "", ...]) dropping
  "", reversed('ab') -> ['b','a'], and getiter(str) via the subscr
  fallback. The fallback logic IS tested via a custom type with a
  subscr slot (tuple_subscr) — see getitem_iter_via_getiter_fallback.
- End-to-end str iteration through the real subscr slot is NOT testable
  in this lane (kind erasure at the slot boundary — the subscr slot
  returns bare PyRaise, so the Stop/Index distinction is unobservable;
  the logic is stub-tested; C13's VM integration covers the live path).
- No attr/method-load helper exists in Rust yet (C12 owns it).
- namedtuple class mro is [] in the fixture (C12 computes real MROs);
  `issubclass(P, tuple)` reads base/mro in C12. P.__bases__ == (tuple,)
  pins base.
- `deque([], 2**62)` abort divergence and the collect_iterable limits
  are documented above.
