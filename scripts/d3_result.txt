§1 — What was built (source -> Rust)
======================================

All modules are pure Rust std, no unsafe, no C FFI. Each follows the
`build_io_module` builder pattern (C18b): `build_<name>_module(ctx,
fun_builtin_var, module_type) -> PyResult<Value>` returning the module
object; registration into `VmState.builtin_modules` is the caller's
(D1/Phase E entry work — see §4). Test fixture per file: local `Fx`
with `setup_<module>` + `run_ok` / `raised_msg` / `g*` read-backs.

math — src/modules/modmath.rs (422) + modmath_tests.rs (463)
  Source: src/modules/modmath.zig (441), table at :376.
  28 fns + 5 constants (e pi tau inf nan), Zig table order.
  generic1/generic2 with the vendor domain-error predicate (result
  nan/inf while input wasn't -> ValueError "math domain error").
  log2/log10 are NOT libm: log(x) * (1/ln 2) / log(x) * (1/ln 10)
  (probed: log2(8) = 2.9999999999999996). ceil/floor/trunc return
  int via C7's int_from_float; frexp via bit decomposition
  (subnormal scale-up by 2^64); modf with inf/nan guards (Rust
  fract(inf) is NaN, C gives 0.0); ldexp via <=1023-exponent
  chunked scaling; gcd as Euclid over BigInt (abs + divmod,
  gcd() = 0, never negative, bool counts as int).
  NO factorial / isclose / gamma (probed AttributeError).

json — src/modules/modjson.rs (691) + modjson_tests.rs (295)
  Source: src/modules/modjson.zig (455). Module name is `_json`
  (table at :431: __name__ encode decode string). encode sig
  (4,4); string sig (2,2); decode sig (1,1).
  Encoder: None/bool/small-int/str/list/tuple/dict + finite float;
  max_depth 256; non-str keys, subclasses, NaN/inf, bytes, sets,
  deep nesting -> TypeError "not handled by the native JSON
  encoder". Escaping: " \b \t \n \f \r, <0x20 -> \u00xx;
  ensure_ascii >=0x7F -> \uXXXX (astral -> surrogate pair).
  ensure_ascii is an IDENTITY check against True (1 is not True).
  Decoder: strict numbers (no leading zero, 1. / 1e rejected);
  strings with \" \\ \/ \b \f \n \r \t \uXXXX; surrogate codes
  D800-DFFF rejected (even valid pairs); trailing garbage ->
  ValueError "not handled by the native JSON decoder". Ints
  <=18 digits -> small int, >18 digits -> parse_num_integer
  (BigInt); floats -> parse_num_float(tok, false). Dict order is
  insertion order (MapData.entries).
  The Python `json.py` layer (petitpy-lib, 387 lines) is D5's,
  NOT ported here.

socket — src/modules/modsocket.rs (741) + modsocket_tests.rs (515)
  Source: src/modules/modsocket.zig (431), table at :367.
  Module globals (11, Zig order): __name__, socket (ctor var
  2..3), fromfd (var 3..4), AF_UNIX=1 AF_INET=2 AF_INET6=10
  SOCK_STREAM=1 SOCK_DGRAM=2 SOL_SOCKET=1 SO_REUSEADDR=2
  SO_PEERCRED=17. Socket type: flags 0x0000, name socket,
  locals dict 10 entries (bind listen accept recv sendall
  setblocking getsockopt fileno close __del__), no print slot
  (default print `<socket>`), no make_new (construction goes
  through the module's constructor function).
  Representation: Obj::Instance { members: empty MapData,
  subobj: [fd, family, type, proto] }, header type the socket
  TypeData, allocated with alloc_with_finaliser (the Zig's
  m_malloc_with_finaliser; the GC drain runs __del__ = close).
  The OS socket lives in a process-global table
  `SOCKETS: Mutex<HashMap<RawFd, SocketState>>` keyed by fd
  (a BuiltinFn receives only CallCtx — no VmState handle —
  and value.rs (886) / gc.rs (830) are both over the cap, so
  no new Obj variant and no arena field; fds are
  process-unique). close() removes the entry (fd closes on
  drop). Operations that can block (accept/recv/sendall)
  work on a dup of the fd (as_fd + try_clone_to_owned,
  safe), never on the table's object, so the lock is never
  held across I/O. `__del__` is the SAME FunBuiltin object
  as `close` (Rust-level test asserts the shared value).
  BuiltinTypes gained `socket: Option<GcRef>` (C13b precedent
  for array/bytearray); build_socket_module returns
  (module, socket_type) and the caller stores Some(type) in
  vm.types.socket. 9 BuiltinTypes literal sites updated with
  `socket: None` (6 test fixtures + vm.rs dummy +
  vm_types.rs build_vm_types).

subprocess — src/modules/modsubprocess.rs (500) + modsubprocess_tests.rs (418)
  Source: src/modules/mod_subprocess.zig (373). Module
  `_subprocess`, sole export `_spawn_and_wait`, sig (8,8):
  (argv, input, timeout, env, cwd, stdin, stdout, stderr)
  -> (returncode, stdout bytes|None, stderr bytes|None,

  reader/writer threads (no libc fork/exec, no poll).

  exec/cwd errnos, OSError otherwise (see §2).

§3 — Bugs found and fixed
==========================

REAL BUGS (in the tree, found by D3's tests/probes)
1. BigInt::set_from_float sign bug (Lane C's, in
   src/vendor/mpz.rs): the adj_exp == 0 arm called
   set_from_int(1), resetting `neg`, so from_float(-1.5)
   was +1 (the code's own comment documented "-1.5 -> +1").
   Fixed by restoring `self.neg = sgn` after set_from_int(1).
   The reference gives int(-1.5) == -1 (probed). The old
   test `set_from_float_negative_one_to_two_quirk` asserted
   the buggy value ("1"); it now asserts the corrected
   values with a comment explaining the history, and
   `set_from_float_cases` already carried the correct
   -1.5/-1.0 cases.
2. `fun_n_args` 8-bit packing limit (mine, found via gcd):
   fun_sig_range decodes (n_args >> 8, n_args & 0xff) — min
   and max are 8-bit each. fun_n_args(0, 0xffff) decodes to
   min=255, max=255, so a var builtin registered with max
   0xffff rejects every call with "argument num/types
   mismatch". Var builtins must use max 255 (the established
   convention: vm.rs print uses (0,255)). Fixed in math gcd
   and used for struct pack/pack_into.
3. `ldexp` powi underflow (mine): 2f64.powi(-1074) is 0.0
   (computes 1/2^1074 -> 1/inf), so ldexp(1.0, -1074) was
   0.0 instead of 5e-324. Rewrote with chunked scaling
   (steps <=1023, early exit on inf/0.0).
4. calc_size_items trailing-digit bug (mine):
   calcsize('2') must raise "bad typecode" (the Zig calls
   binary_get_size(fmt_type, 0)); initially returned (0,0).
5. `record_raise` first-wins shadowing (mine, in
   subprocess): str_arg records TypeError, then the
   EINVAL remap in str_list_arg/cwd_arg was ignored, so
   ["..."/bin/true", 123] raised TypeError instead of
   OSError(22). str_list_arg/cwd_arg now use str_bytes_of
   directly (no prior record). Confirmed by the stale-run
   output before the fix.

TEST BUGS (mine, all fixed in the tests, not the code)
- struct pack '<s' is 1 byte (no count means 1):
  pack('<s', 'ab') == b'a', not b'ab'; same for unpack.
- struct unpack_from offset -4 on a 5-byte buffer reads
  index 1 -> (0,), not (1,); the test now uses -5.
- json encode call passed only 3 args (missing True) — the
  TypeError "argument num/types mismatch" was CORRECT
  behaviour (sig (4,4)), verified on the reference.
- `ok = ok and ...` chains rewritten to single `assert`
  statements (see the VM bug below).

A REAL VM BUG FOUND BY D3 (NOT fixed in this lane — C13's)
- `and` with a False left followed by a call raises
  TypeError("object not callable") in the Rust VM: the
  JUMP_IF_FALSE_OR_POP path leaves the stack misaligned
  when the jump is taken, so the following call pops a
  wrong callee. Minimal repro (reference prints False
  cleanly):
    import struct
    ok = False
    ok = ok and struct.pack('<i', 1) == b'\x01\x00\x00\x00'
  Preserved as #[ignore]d test
  `modstruct_tests::and_false_shortcircuit_vm_bug` (with a
  comment); the fixing lane removes the #[ignore]. D3's own
  tests avoid the pattern (single `assert` statements).
  Every pack/unpack/json line passes in isolation; the chain
  failed only once an intermediate link went False — that is
  how the bug was bisected.

§4 — Not done, divergences, handovers
======================================

Divergences (all documented in the module docs too)
- math: ldexp(1.5, 2**40) saturates instead of aborting
  (reference rc=134, @intCast panic).
- struct: pack('<s', 123) zero-fills instead of aborting
  (reference rc=134, uninitialised buffer); 'S' get is
  empty str (C9b limit, reference rc=134 on null).
- socket: constructor cannot call socket() in pure std —
  placeholder /dev/null fd, bind() swaps in the real
  listener (fd number changes across bind(); a client
  connecting between bind() and listen() is accepted;
  listen(backlog) is a validation no-op after bind()).
  fromfd with a non-negative fd raises NotImplementedError
  (wrapping a foreign fd needs from_raw_fd / borrow_raw,
  both unsafe; this lane is pure-std with no unsafe).
  fromfd(-1) works (behaves like a closed socket).
  getsockopt raises OSError(ENOPROTOOPT) for every
  (level, opt) — no stable-std getsockopt (peer_cred is
  unstable); the reference returns real bytes (12-byte
  ucred for SO_PEERCRED). Integer args truncate to i32
  (the Zig's @intCast would abort on overflow).
  bind("") returns ENOENT (reference binds an
  abstract-named socket). listen() on a fromfd listener
  fd is EINVAL (role unknowable without SO_ACCEPTCONN).
  The socket __del__-via-GC-finaliser path is UNTESTED
  (needs the gc module, D4's); explicit close() is tested.
- subprocess: timeout kill is SIGKILL (returncode -9),
  not the Zig's SIGTERM (-15), and no 1s grace period
  (no SIGTERM in std). A file-descriptor stream mode is
  served by re-opening /proc/self/fd/<fd> (works for pipes
  and freshly-opened files; does not share the original's
  file offset or append mode; a socket fd fails ENXIO).
  An env entry without '=' is passed as (entry, "") (the
  child sees "FOO="; the reference passes "FOO" through).
  argv as str/tuple and env as str ABORT the reference;
  this port returns OSError(EINVAL). input=123 HANGS the
  reference; this port raises TypeError.
- json: the Python json.py layer is D5's, not ported.
  subprocess.py (run/check_output/call/CompletedProcess)
  is D5's, not ported.
