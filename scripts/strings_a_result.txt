## 测试发现的真 bug（已修复）

- `slice_load_bytes` 慢速路径误用了 `fast_slice_indexes` 的 bounds：`fast_slice_indexes` 对负 step 做 `stop += 1`，`slice_count` 不能看到调整后的 stop。`"abc"[::-1]` 返回了 `"cb"` 而非 `"cba"`。修复：慢速路径改用 `slice_indices` 重新解析（与 `slice_load_str` 已有做法一致）。修复后 `[::-1]` / `[::-2]` / `[3:0:-1]` / bytes `[::-1]` 全部正确。
- `find_family` 的一个期望值写错：`"abc".find("b", 2)` 我最初按旧探针记录写成 4；重新对参考二进制探针确认是 **-1**（`"abc".find("bc",2)` 也是 -1；`"abc".find("bc",1)`=1，`"abc".find("c",2)`=2）。旧记录有误，以本次新鲜探针为准；实现本身是对的。

## 有意分歧（原文在参考二进制上崩溃 rc=134，Rust 抛 intended error / 返回 self）

- `str(1,2,3,4)` / `str(123,'utf-8')`：Zig 的 void `mp_arg_check_num_sig` 未能阻止执行，`makeNewDefaultOther` 忽略 `mp_get_buffer` 失败，读垃圾指针进 qstr hash → 崩溃。Rust：`str_make_new` 对 4 args 抛 `ArgNumTypesMismatch`；`str(123,'utf-8')` 抛 TypeError "object with buffer protocol required"。
- `b'ab'.hex(1)`：Zig panic "incorrect alignment"（small int 当指针读）。Rust：`bytes_hex` 对非 str/bytes sep 走 `str_check_arg_type` 报错。
- `"abc".strip(1)`：`strUniStrip` 在 `str_check_arg_type` 后不查 pending_exc，把 int 当 `MpObjStr` 读 → misaligned-pointer panic。Rust：`str_strip` 抛 TypeError "can't convert to str implicitly"。
- `"abc".zfill(-1)`：Zig panic "integer does not fit in destination type"（负 isize → usize 的 @intCast）。Rust：`str_zfill` 对负 width 返回 self。
- `str(1,2,3,4)` 之外的多参路径：`str('a','b','c','d')` 原文正常抛 "argument num/types mismatch"（与 crash 路径不同，`str_make_new` 的 sig check 在该路径生效）；`bytes('a','b','c','d')` / `bytes(1,2)` 原文显式抛 "wrong number of arguments"——两者文本不同，均已探针确认并分别实现（`ArgNumTypesMismatch` vs `WrongArgs`）。

## 设计决策（本 lane 内部；冻结接口未动）

- 方法 fn 取 `(ctx, types, args)`（C6 前例）；槽 fn 只有 `ctx`，经 `INSTALLED_TYPES` thread-local 取 `&BuiltinTypes`（仿 C6 测试 harness 的 `TEST_TYPES` 前例）。C13 扩充 `CallCtx` 后以 `CallCtx` 携带的引用替换该 cell。
- `PENDING_STR_ERROR: Cell<Option<(StrExc, Option<&'static str>)>>` 是 Zig `pyerr.pending_exc` 全局的替身，待 C13 落地 `VmState.pending_exc`（设计文档 D7）。槽抛专属错时先 `slot_raise(e)` 再返 `PyRaise`；槽返 NULL（原文）时不记任何东西。
- **已知缺口（C13）**：C6 的 `call_unary` / `call_binary` / `call_subscr` 把每个槽的 `PyRaise` 都折成 `SlotOutcome::NotImplemented`，`obj_subscr` 再抛通用 `ObjError::NotSubscriptable`（"object isn't subscriptable"）——如 `"abc"[5]` 在分发层会表现为 TypeError 而非 IndexError "string index out of range"，直到 C13 让 wrapper 查 pending cell。专属 (type, message) 保存在 cell 里，可经 `take_pending_str_error()` 测到；测试 `subscr_dispatch_and_pending` 同时断言了分发层的通用错和 cell 里的专属错，把该缺口钉死。
- `BuiltinFn` wrapper 从 installed cell 取 types；VM 如何把 types 线程进方法是 C10/D1 的接口问题，本 lane 不改冻结签名。
- `KwArg { name: u32, value: Value }` 是最小临时形态（只有关键字名有意义——encoding/errors 的值原文解析后忽略）；运行时调用协议（C10/C13）拥有规范的 kwargs 表示。
- `buffer_data`：str/bytes 经 `str_data` 读；非 str/bytes 对象的 buffer 没有安全读取器（`BufferInfo` 里的裸指针需 `unsafe` 读，全仓无 `from_raw_parts`）→ 报 `BufferProtocol`（已文档化的 C9 缺口；今天 str/bytes 是仅有的 buffer 提供方，C9 在 array/bytearray 落地时加安全拷贝）。
- 借用模式（本 lane 3 次踩到）：`str_data` 返回借 arena 的 `&[u8]`，任何分配调用前需先拷到 owned `Vec`，或先抽出借用再分配。
