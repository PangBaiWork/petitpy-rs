§3 Leftover issues / interface gaps vs brief §2.3
--------------------------------------------------
(a) NO FfiSocket use. `modsocket_ffi.rs` does not exist
    in this worktree (S1 builds it in parallel).
    create_connection / create_server / socketpair go
    through the existing `socket_ctor` + method dispatch
    (they compile without S1's file and dispatch to FFI
    once S1 lands). No method I needed was missing from
    §2.3 for the S2 surface — but see (b) and (f).
(b) socketpair is std emulation, NOT `socketpair(2)`:
    INET/INET6 = loopback TCP pair via std TcpListener;
    AF_UNIX (Unix) = temp-path emulation
    (`temp_dir()/petitpy-sp-{pid}-{counter}`, bind ->
    connect -> accept -> unlink) because
    `SocketAddr::from_abstract_name` is unstable on
    rustc 1.99.1 and S1's `sys_socketpair` /
    `FfiSocket::from_raw` are not in this worktree.
    Functionally identical; replace with the real call
    when those land. AF_UNIX on Windows =
    NotImplementedError.
(c) Duplicates to dedup at merge (marked in the code):
    `ffi_dns.rs` redefines `Sockaddr` / `SockaddrIn` /
    `SockaddrIn6` / `SockaddrStorage` / `Addrinfo` /
    `Servent`, plus `errno()` and `ensure_winsock()` —
    S1's `ffi.rs` §2.1 has the canonical ones; delete
    the `ffi_dns.rs` copies at merge and use S1's.
    (`AddrInfoEntry` / `ResolvedAddr` / `NameInfoAddr`
    and the `*_owned` helpers are S2's own and stay.)
(d) Windows / macOS / Android branches are UNVERIFIED
    locally (local cross-compile is forbidden by the CI
    constraint). The cfg'd code follows the brief §2.2 /
    §6 tables (Windows `Addrinfo` layout, WSA codes,
    `inet_aton` absent on Windows, `SO_RCVTIMEO` DWORD
    vs timeval); CI must compile them.
(e) Deliberate divergences (functional equivalence, not
    byte-for-byte, per the user's 2026-11-20 verdict):
    - getaddrinfo 5-tuple echoes the REQUESTED type/proto
      (CPython returns the resolved ai_protocol, e.g. 6).
      Pinned by modsocket_tests (type defaults to
      SOCK_STREAM when omitted).
    - IPv6 addresses are 2-tuples (host, port); CPython
      returns 4-tuples (flowinfo, scopeid dropped).
    - gethostbyname_ex / gethostbyaddr alias lists are
      always empty (getaddrinfo/getnameinfo have no
      aliases).
    - create_connection/create_server `all_errors`:
      raises the FIRST error (CPython 3.12 raises an
      ExceptionGroup, which this VM has no support for).
    - inet_aton/inet_pton/inet_ntop/inet_ntoa accept str
      as well as bytes (lenient vs CPython's bytes-only
      for packed forms).
    - htonl/htons mask to width (Linux truncation;
      Windows raises for out-of-range).
    - getaddrinfo unknown service is OSError(-2)
      (EAI_NONAME) per the pinned test; glibc/CPython
      report -8 (EAI_SERVICE) for an unknown service
      name (verified directly). `ffi_getaddrinfo`
      maps EAI_SERVICE -> table retry -> EAI_NONAME
      when the name is unknown.
    - getaddrinfo accepts 2-5 args only (no `flags`
      parameter) — pre-existing H-socket limitation,
      unchanged.
(f) `getsockname` / `getpeername` did NOT exist (the
    brief §2.4 lists them among the "existing" methods,
    but grep shows zero references — same for
    `shutdown`, which I did NOT add). I implemented
    them on the pure-std path in dns.rs (local_addr /
    peer_addr; INET -> 2-tuple, UNIX -> path str;
    unconnected getpeername -> ENOTCONN) and registered
    them; `create_server`'s test needs `getsockname`
    to learn the ephemeral port. S1 must add the
    `SocketState::Ffi` arm to both at merge (the
    variants are listed explicitly, so the match goes
    non-exhaustive when `Ffi` lands — a compile error
    will force the addition). `shutdown` is still
    absent (S1/S3 scope).
(g) `migrate_settings` deadlock (pre-existing H-socket
    bug, FIXED in this lane — modsocket.rs): the old
    code did `if let Some(s) = settings().remove(&old)`
    then `settings().insert(new, s)` inside the body,
    re-locking the same non-reentrant Mutex while the
    temporary guard was held. It hung forever whenever
    a settings entry existed (setsockopt / settimeout /
    setblocking / setdefaulttimeout) and bind/connect/
    dup changed the fd. Proved by probe:
    setsockopt-then-bind and settimeout-then-bind both
    hung; plain bind worked (no entry -> remove returns
    None -> no second lock). This blocked
    `create_server` (which must set SO_REUSEADDR
    before bind). Fix holds ONE guard for the move.
(h) `h_select_dup_fd` (lib) and
    `select_readable_fd_is_ready` (integration) are
    LOAD-DEPENDENT flakes in the readiness monitor
    (select with timeout 0 before the monitor thread
    reports the fd): each failed once under full-suite
    load and passed on retry / 5x in isolation. Pre-
    existing, unrelated to this lane (no sockets in
    the first; the second is /dev/null + select).
    Not fixed here.
(i) `cargo test --release --tests` (all targets at
    once) hit the known LTO stale-object link flake
    twice when switching features in one target dir;
    plain rerun fixed it both times (documented
    behaviour, not a code issue).
(j) The feature DEBUG full lib suite still aborts
    with the pre-existing "IO Safety violation"
    (baseline issue, unchanged by this lane); release
    lib is clean on both builds.
(k) `create_server` with AF_UNIX: address is a path
    (str/bytes), not a tuple — implemented
    (`create_server_unix_impl`, Unix only; Windows ->
    NotImplementedError). Not in the brief's text but
    CPython accepts it, so it is supported.
(l) `getaddrinfo` flags: the module function takes no
    `flags` arg (see (e)); `resolve_addrs` (for
    create_connection/create_server) passes AI_PASSIVE
    internally where needed.
