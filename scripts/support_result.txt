FINDINGS (all verified against the original source; probes where noted)
  - isNonblockingError is literally `return false` (MICROPY_STREAMS_NON_BLOCK=0
    under MINIMUM ROM level) — every non-blocking branch in stream.zig is dead
    code, so backends return PyResult<usize> (Err = MP_STREAM_ERROR + errcode).
  - mp_get_stream_raise: the Zig @panics when the type lacks the protocol;
    vendor C raises OSError("stream operation not supported") — Rust follows C.
  - streamReadGeneric's TEXT branch passes MP_STREAM_RW_READ, NOT the caller's
    flags — read1 on a text stream loops exactly like read (tested).
  - streamReadintoWriteGeneric buffer flags are CROSSED: WRITE reads FROM the
    buffer (MP_BUFFER_READ), READ writes INTO it (MP_BUFFER_WRITE).
  - Vendor mp_obj_str_get_buffer refuses BUFFER_WRITE ("can't write to a
    string") — so readinto into str/bytes is TypeError on the reference too;
    write-back targets are only Array (bytearray / memoryview, tested incl.
    view-through via the source chain, free*sz per hop).
  - streamUnbufferedReadline's max_size is mirrors.smallIntValue — a RAW
    tag-unshift, not a conversion: SmallInt→itself, True(30)→15, False(14)→7,
    None(6)→3, qstr ((q<<3)|2)→4q+1, heap object→huge pointer-shifted number
    whose vstr_init fails with MemoryError (all tested).
  - read1 / write1 / readinto1 are NOT static qstrs — absent from
    qstrdefs.generated.h too (the original interns them dynamically at type
    setup). D must resolve those three via the runtime pool; the other 11
    STREAM_METHODS names are static (asserted in the table test).
  - read(sz): sz==-1 → readall; sz<-1 → MemoryError (vstr_init_len);
    read(0) → empty. mp_stream_rw: 0 return = EOF/no-progress; ONCE returns
    the first call's count. mp_stream_seek returns the offset via SeekState,
    not the ioctl return. streamReadall calls stream_p.read DIRECTLY in
    256-byte chunks (not mp_stream_rw).
  - Huge vstr allocations go through try_reserve_exact/try_reserve so they
    fail with OutOfMemory instead of aborting (Vec::with_capacity would abort).
  - Two failures hit during the lane, both fixed in-lane: (a) the table test
    asserted all 14 names static — read1 is genuinely dynamic (finding above,
    not a bug); (b) the readinto off/max_len expectation miscounted the
    5-byte destination ("he_ll", not "he_ll_") — test bug, implementation was
    already correct.
