§3 — Findings (all probed on the reference binary unless noted)
---------------------------------------------------------------
3.1 `pow(2, 3, mod=None)` → TypeError "pow() with 3 arguments
requires integers" — a PRESENT `mod` kwarg (even None) selects
the 3-arg path. CORRECTS the pre-dispatch probe "pow(2,3,
mod=None)=8" (that script aborted at `round(1.234, 2.0)`
before reaching the pow line). `pow(2, 3, None)` positionally
→ same error. Implemented in `pow_builtin_kw` / `pow_builtin`
(present-kwarg detection via `kw_lookup`).

3.2 STORE_ATTR pop order (real bug in master, C13-era): the
compiler pushes the VALUE first, then the base — the stack is
`[value, base]` with the base on top (CPython's convention;
`vm.zig:657-662`: `mp_store_attr(sp[0], q, (sp - 1)[0])`,
`sp[0]` is the top). The Rust handler popped `v` first, then
`base` — swapped — so `c.x = 7` stored attr `'x'` on the int
`7` (Kind::Other → AttributeError "no attribute 'x'"). Fixed
in vm_dispatch.rs (pop base, then value). This is why
`setattr(c, 'x', 7)` passed while `c.x = 7` failed: same
`store_attr_ctx`, different (wrong) argument order at the
opcode. `makenew_class_member_store` now passes.

3.3 str LEN/BOOL on string literals (real bug in master):
`str_unary_op` used the static-only `str_data` (resolves only
qstr ids < 613), so `len('abc')` / `bool('')` on a dynamically-
interned literal raised TypeError "object has no len". Fixed
with `str_data_pool` (pool-aware, C13's note left this arm
open). Also fixes `sorted(..., key=len)` on strings.

3.4 Getitem-iterator exhaustion (real bug in master): the VM
`for`/`min`/`max` path over a str raised IndexError "index out
of range" at exhaustion instead of stopping. Cause: the slot
collapses its error into a recorded raise (`call_subscr`
turns a slot `PyRaise` into `NotImplemented`), so
`obj_subscr` never returns `IndexOutOfRange` and the getitem
seam's `Err(IndexOutOfRange) => Stop` arm never fired. Fixed
in `iternext_allow_raise_ctx`'s getitem seam: classify on the
recorded raise — the original's rule
(`objgetitemiter.zig:excIsStopOrIndex`): a `StopIteration` or
`IndexError` from `__getitem__` IS exhaustion (pending raise
cleared); anything else propagates.

3.5 `repr(None)` printed `"<NoneType>"` in master: the VM's
`none_type` was built by `plain_type` with NO print slot, so
`obj_print_helper` fell back to the default `"<{type}>"`.
The original carries `none_print` (vendor objnone.c,
mp_type_roms.zig:191-201 — prints "None", JSON branch dead
under full). Added `none_print` (vm_builtins.rs) and wired it
into `none_type` in `build_vm_types`.

3.6 `min([])` / `max([])` raise ValueError "arg is an empty
sequence" (not TypeError) — the Zig's `raiseMinMaxEmpty`.
Fixed with the new `value_error` helper.

3.7 `round(2.5, None)` ≡ `round(2.5)` — the Zig checks
`args[1] == OBJ_NONE` for the POSITIONAL 2nd arg too, not just
the kwarg. Fixed in `round_impl` (positional `None` normalises
to the 1-arg form; `round(1.234, 2.0)` still raises
"can't convert to int").

3.8 `isinstance` / `issubclass` were never bound in
`build_builtins` (the `Rom`-built FunBuiltin objects existed
but no name pointed at them) — `isinstance(1, object)` raised
NameError. Bound now via the same constructors `Rom` uses
(`isinstance_fun_obj` / `issubclass_fun_obj` over fresh empty
dicts).

3.9 `dir(1)` == `['__class__', 'from_bytes', 'to_bytes']`;
`dir('ab')` starts `['__class__', 'count', 'endswith', 'find',
'format']`; `dir(1.5)` == `['__class__']`; `dir()` inside a
function returns the MODULE globals (locals == globals at
module level in Rust — matches). `__dir__` delegation works
(`dir(D())` → `['z', 'a']`).

3.10 `min([3, 1, 2], key=None)` → TypeError "object not
callable" (explicit `key=None` IS called); `sorted([3, 1, 2],
key=None)` == `[1, 2, 3]` (sorted treats None as absent);
`min([1], foo=1)` == 1 (min/max's `unpackMinMaxKwargs` reads
ONLY `key`/`default` — unknown kwargs ignored); `sum([1],
foo=1)` → TypeError mismatch (sum enforces its kw set).

3.11 `sorted` ties keep their original order, with and without
`reverse=True` (stable, CPython-like — probed).

3.12 `chr(0xD800)` → a 1-char string (`len` == 1,
`ord` == 0xD800, CESU-8 bytes ED A0 80); `round(True)` == 1,
`round(False)` == 0; `round(2.675, 2)` == 2.68 (ties-to-even
on the exact IEEE product 267.5).

3.13 `print("hello", file=s)` into a StringIO works on the
reference — Rust `print` still IGNORES `file=`/`flush=` (no
`sys.stdout` yet — D2, §4).

3.14 `vars` is NOT in the `modbuiltins.zig` table (verified in
the source) — not bound, as the brief's grounding resolved.

§4 — Handovers / known limitations
----------------------------------
- `open` is a `NotImplementedError` stub ("open() not implemented
  yet (D2)") in `builtin_fns.rs` (`open_builtin` /
  `open_builtin_kw`); the io module's `open` member is this same
  FunBuiltin value. D2 fills the body in place. Sig: kwVar,
  min 1, max 0xffff, kw=true (`file_io.zig:518-529`).
- `print(file=)` / `flush=`: DEFERRED to D2 (needs `sys.stdout`
  as a stream object over fd 1; `stream_write_adaptor` exists).
- `extensible_modules` left empty (D3/D4 fill it — the original's
  extensible modules are modarray/moderrno/modstruct, NOT io).
- FunBc dunder limitation (pre-existing, same class as C13b's
  FunBc-collect gap): `binary_op` calls use stub seams, so a
  user-defined `__lt__` / `__abs__` via FunBc raises PyRaise in
  both the VM expression path and D1's builtins (min/max/sum/
  sorted key comparisons). A VM-seam-aware collect/comparison
  path is still needed (C15/D).
- `sorted(key=...)` when the key CALL fails: Rust propagates
  the error; the reference ABORTS rc=134 (e.g. `sort(key=len)`
  on ints — the NULL key result is passed to the comparison,
  `fromPtr(NULL)` panics at `mp_mirrors.zig:745`). Documented
  divergence, same as C9b's list_sort doc.
- `binary_op_plain` does NOT reproduce the dispatcher's
  `native_subclass_op` / typing-union arms — user subclass
  binary-op overrides are not honoured by plain builtins
  (divmod/pow/sum); the VM expression path has them.
- `makenew_class_attr_on_class` (`C.x` — `load_method_maybe_ctx`
  looks in `type`'s dict) is NOT fixed by D1 — stays ignored in
  vm_tests_b.rs (C14's real `mp_load_method` exists in
  runtime_method.rs but the VM dispatch still uses the local
  approximation).
- `input()` reads fd 0 / writes fd 1 in production (std
  stdin/stdout); the Ctrl-C path (0x03 byte → KeyboardInterrupt)
  and EOF path (empty + Ctrl-D → EOFError) are tested at
  `CallCtx` level only (`input_read` over Cursor/Vec).
- vm.rs is 792 lines (8 headroom) and vm_call.rs 790 (10
  headroom) after the D1 split (`vm_builtins_bind.rs` holds the
  D1 binds; the stale top-of-file doc bullets were trimmed).
  A future lane adding to either file must split again before
  adding. value.rs stays 886 (recorded cap debt, unchanged).
