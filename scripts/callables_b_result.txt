FRAME DECISION: (b) C13-side — do NOT embed CodeState in GeneratorData
----------------------------------------------------------------------
gen_wrap_call returns (GcRef, CodeState); every resume function
takes `&mut CodeState` as a parameter; the VM owns the frame and
associates it with its generator.

Reasons:
1. value.rs must not depend on runtime::bc — embedding CodeState
   there would be a `value` <-> `bc` module cycle (value.rs is the
   bottom of the objects layer; bc.rs already imports value).
2. The Zig's MpCodeState is exactly C5's CodeState plus `sp` and
   `old_globals`, which already live outside it in Rust (the value
   stack and the globals save/restore are the VM's job — see the
   runner seam below). There is nothing generator-specific left
   to embed.
3. The Zig's `n_exc_stack` is decoded but unused (Rust's CodeState
   has no exception stack; C5 discards it the same way).

GeneratorData was extended instead with two fields:
  { fun: GcRef, state: GenState, pend_throw: Option<Value>,
    stop_value: Option<Value> }
- pend_throw is the Rust spelling of the Zig `pend_exc` tri-state
  (None == OBJ_NONE, Some(v) == queued throw; Running == pend_exc
  == OBJ_NULL).
- stop_value is the Rust spelling of the thread `stop_iteration_arg`
  (makeStopIteration), stored per-generator so `yield from` reads
  the right one (None == returned None, the Zig's OBJ_NONE ->
  OBJ_NULL mapping).

Zig -> Rust mappings pinned in the code:
- code_state.ip == 0 (already-stopped) -> GenState::Closed. (Rust
  `ip` is a byte offset; 0 is valid after setup, so it cannot be
  the marker.)
- sp == state - 1 (just-started) -> GenState::New. (Rust CodeState
  has no `sp`.)
- pend_exc == OBJ_NULL (running) -> GenState::Running.
- ret_val + VM_RETURN_* -> GenResume.
- makeStopIteration(v) -> Ok(None) from iternext (C11 convention)
  with the value stashed in stop_value; send/throw raise
  GenError::StopIteration(value) on exhaustion instead.

RUNNER SEAM (LOCAL to C10b, defined in objgenerator.rs)
------------------------------------------------------
To be unified with C10a's seam by the main agent at merge; C13
is the consumer.

  pub enum RunOutcome { Normal(Value), Yield(Value), Exception(Value) }
  // VM_RETURN_* kind + value — yielded/returned/raised value handed
  // over by the runner, because the value stack lives in the VM,
  // not in CodeState.
  pub type GenRunner<'a> = dyn FnMut(&mut CallCtx<'a>, &mut CodeState,
      Value, Option<Value>) -> RunOutcome + 'a;
  // args are (ctx, frame, send, throw): send is the value to deliver
  // as the pending `yield` result, throw is the exception to inject
  // (None = plain resume). The runner owns the value stack and the
  // globals save/restore.
  pub struct GenResume { pub kind: ResumeKind, pub value: Value }
  pub enum ResumeKind { Normal, Yield, Exception }

gen_wrap_call splits exactly as the brief required: the prelude
decode -> mp_setup_code_state (C5's, already ported) part is fully
portable/testable (incl. the B2 polled-sentinel at objgenerator.zig
:353 — setup errors surface as GenError::Setup), and the execute
step is the `runner` parameter. Tests drive the full call with a
scripted stub runner (script_runner in the test file: queued
RunOutcomes + an (send, throw) log).

Note for the unifier: the test helper script_runner logs into an
Rc<RefCell<Vec<...>>> (shared &Rc), NOT a &mut Vec. A &mut log
fights the borrow checker here: the runner's GenRunner<'a>
lifetime is unified with the CallCtx lifetime at the call site,
so a mutably-borrowed log cannot be read after a call while ctx
is still used later in the same test. The Rc<RefCell> log is
readable at any time.

Brief premises that turned out WRONG (Zig wins)
------------------------------------------------
(a) gen_instance_throw's Zig signature is (n_args, args) with NO
    self_in — args[0] IS self, user args are args[1..]. The Rust
    API takes `gen` separately + user args after self.
(b) gen_instance_pend_throw is NOT dropped — the header comment's
    "Dropped" list is stale; the body exists behind the full-config
    gate and the full locals dict has 4 entries (nano 3).
(c) throw(type, value) does NOT instantiate the type — the second
    arg, if not None, IS the exception passed through; validation
    ("exceptions must derive from BaseException") happens in the
    VM inject path (C13), not in gen_instance_throw.
(d) Test-fixture note (not a brief premise): "MyStop"/"MyExit"
    are NOT static qstrs — exc_type now falls back to interning
    non-static names in the runtime pool (RuntimeQstr::from_str,
    ids start at N_TOTAL), instead of expect()ing a static id.

Subclass checks: no StopIteration/GeneratorExit type objects exist
yet (C12), so exc_is_subclass_named walks the raised value's
header-type MRO by type NAME (exact until C12 provides type
identity; handles a fixture-built subclass with a hand-populated
mro). gen_instance_close takes the GeneratorExit singleton
instance as a parameter (C12 creates it, C13 passes it).

DEFERRED to C13 (exact list, with Zig line refs)

1. The actual bytecode execution step — mp_execute_bytecode
   (objgenerator.zig:~366, inside fun_bc_call's call path and
   gen_resume's step): the runner seam's real implementation.
   The globals save/restore around the step (globalsGet /
   globalsSet, objgenerator.zig:~360-366) is the runner's job

   currently returns PyRaise. C13 wires the code store —

   gen_wrap_call takes `code: &RawCode, qstr_table, extra_args,
   empty_tuple` explicitly; C13's Vm supplies them from its code
   store.
3. The four gen_instance_*_builtin stubs (objgenerator.zig:282
   send, :286 throw, :295-314 close, :324-331 pend_throw):
   arity-checked, then PyRaise. They cannot take a runner through
   the frozen BuiltinFn signature until C13 grows CallCtx into
   the Vm (design doc D5).
4. The GeneratorExit singleton instance (mp_const_GeneratorExit_obj)
   and the StopIteration / GeneratorExit TYPE objects (C12
   creates them): gen_instance_close takes the GeneratorExit
   instance as a parameter; C13 passes it. The PEP 479 check and
   the close-path GeneratorExit check currently use
   exc_is_subclass_named (MRO walk by type NAME); C12 must
   replace it with type-identity checks.
5. The VM inject-path validation for throw ("exceptions must
   derive from BaseException", objgenerator.zig:286-292):
   gen_instance_throw passes args through; the VM validates.
6. makeStopIteration (objgenerator.zig, StopIteration
   construction): gen_resume stashes the return value in
   GeneratorData.stop_value; the VM must read it when raising
   StopIteration from iternext/send/throw exhaustion (and map
   GenError::StopIteration(value) to a real StopIteration
   exception object). Likewise GenError::Raised carries the
   exception object; the VM must install it as pending_exc
   (design doc D7; PENDING_STR_ERROR / the C6 convention of
   dropping raise data at slot boundaries ends here).
