§3 — Bugs found + brief-premise corrections
-------------------------------------------
1. [BRIEF PREMISE CORRECTED] sys.exc_info() is ALWAYS
   (None,None,None). The brief assumed a cur_exception slot;
   grep found NO `cur_exception =` assignment anywhere in src/
   or vendor/; src/runtime/vm.zig:187 says "SYS_EXC_INFO=0 ->
   no MP_STATE_VM(cur_exception) write"; full_stubs.zig exports
   a null storage slot. Implemented as a constant
   (None,None,None), NO VmState slot.
2. [BRIEF PREMISE CORRECTED — pre-existing divergence, now
   visible] The entry module registers into state.modules
   (load_module_from_mpy calls register_mpy_code(..., true)),
   so D2's live sys.modules mirror shows "<test>" (and every
   entry module). The reference prints sys.modules == {} for
   BOTH petitpy-vm (entry.mpy) and petitpy (script). The mirror
   faithfully reflects state.modules; the fix belongs to Phase E
   entry work (decide whether the entry module registers).
3. attrtuple attr slot never wired: attrtuple_type_data set
   attr: None although attrtuple_attr (objattrtuple.rs:105)
   exists — sys.implementation.name raised AttributeError at
   the VM level. Fixed: attrtuple_attr_fn adapter +
   attr: Some(attrtuple_attr_fn). (Check D1 overlap at rebase —
   D1's notes do not mention it.)
4. STORE_ATTR pop order swapped + store_attr_ctx a stub:
   store_attr_ctx always raised AttributeError; the dispatch
   popped value first then base, but the Zig's mp_store_attr
   (vm.zig:657-661) has stack [value, base] with BASE on top.
   Fixed in-lane. DUPLICATE of D1's later merge (2026-11-18
   ~08:28, commit 2140ecf) — at rebase take D1's version (C14's
   full runtime_method::store_attr) and DROP D2's hunks
   (vm_rt_name.rs module branch, vm_dispatch.rs pop-order).
5. ROT_TWO/ROT_THREE destroyed NULL slots: sset always wrote
   Some(v), both arms used unwrap_or(Value::None) — so
   LOAD_NULL; ROT_TWO; STORE_ATTR (del x.attr) arrived as a
   store of the None object, and `del sys.path` silently
   succeeded. Fixed: sset takes Option<Value> and writes it
   raw; ROT_TWO/ROT_THREE pass sget results through unchanged.
   UNIQUE to D2 (D1's merge notes do not mention it) — KEEP at
   rebase.
6. [BUG, found by the _environ tests] os._environ() hand-rolled
   its dict with ctx.alloc(None, ...) — header None, so type
   dispatch could not see it as a dict: e1 == e2 was False
   (fell back to identity) and e1[...] raised TypeError
   "object isn't subscriptable". Fixed: build with dict_new
   (proper dict type header). Lesson: never hand-roll a dict
   (or any typed object) with a None header.
7. [TEST-HARNESS RACE, not an implementation bug] The
   objfileio tests first shared one temp dir across parallel
   test threads — cleanup raced (DirectoryNotEmpty / NotFound).
   Fixed: per-test temp dirs (pid + test tag).
