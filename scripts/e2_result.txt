## §1 — Runners and the comparison rule of each gate (as read from the original)

(a) Corpus full gate — scripts/run_full_gate.py (exists since the
lane's start; imports the original's tools/full_gate.py, overrides
full_gate.BIN, calls its entry point). Rule (full_gate.py:40-90):
run [BIN, script], compare stdout+stderr+"\n[exit N]\n" byte-for-byte
against corpus/full/basics/<name>.out, timeout 10s; bidirectional vs
corpus/full-known-fails.txt (7 names). Verified vs the reference
binary first: exactly 545/552 with the same 7 fails.
Second view: tools/corpus.py verify --config full <BIN> — DUPLICATES
(a) (same goldens, cwd=script's parent, timeout 30s instead of 10s);
run once as a confirmation: PASS 459/552 FAIL 93, identical to (a).
Its "standard oracle" (the default reference for `gen`) is the vendor
MicroPython build-standard binary, which does NOT exist in this VM.

(b) Integration — scripts/run_integration.py (thin wrapper around the
original's tests/integration.py, run from the original repo root).
Rule (tests/_integration_runner.py): run [binary, tmpfile.py], stdout
compared exactly (expected=None skips the stdout check), exit code
checked when given as the 4th tuple element, timeout 30s, config full.
202 cases (CORE + OS).

(c) Golden programs — scripts/run_golden.py. There is NO
tools/golden_run.py (README reference stale; only
tools/golden_bootstrap.py exists). The bootstrap's rule
(evaluate_program): a petitpy run "passes" if its COMBINED
stdout+stderr, normalized (rstrip per line, strip overall), matches
EITHER MicroPython's OR CPython's, and did not time out
(TIMEOUT_SECONDS=10, cwd=script's parent dir). ADAPTATION, recorded
here deliberately: the vendor MicroPython oracle does not exist in
this VM, and matching CPython alone would measure CPython-divergence,
not petitpy-fidelity (petitpy deliberately differs from CPython, e.g.
hash(2**70)==0). So the oracle here is the REFERENCE petitpy binary
itself, with CPython kept as a second, informational column
(rust==cpython count): PASS iff the Rust run's normalized combined
output equals the reference petitpy run's (no timeout on either side).
Verified vs the reference first (bin=reference): 584/584 + 1/1.
File counts verified: works/ 584 .py, works-native-only/ 1 .py.

(d) Capability — scripts/run_capability.py (imports the original's
tools/capability_matrix.py, overrides ZIGPY/VM to the Rust
zigpy-compile / petitpy-vm binaries, calls main(["--gate"])).
Rule: for each of the 67 CONSTRUCTS, compile with the front-end to
.mpy, run the back-end (petitpy-vm) on it, stdout must equal CPython's
stdout exactly (rc != 0 -> FAIL, else ok/diff); gate is bidirectional
vs corpus/capability-known.txt (baseline EMPTY — only comments).
Only back-end gaps (FAIL), back-end splits, and front-end splits are
gated; a front-end gap is a measurement, not a defect, and a CPYTHON
DIFF (back-ends agree, differ from CPython) is not gated either.
`compile_pyfront` is stubbed to return False: pyfront needs
`uv run --project projects/pyfront`, and `uv` is NOT installed in
this VM, so that column is unmeasurable here (the original's
compile_pyfront would raise FileNotFoundError). The vendor
MicroPython column (UPY) is absent too (no
vendor/micropython/ports/unix/build-standard/micropython), so that
column is always None. Verified vs the reference first (reference
zigpy-compile + petitpy-vm): GATE: GREEN, with 1 CPYTHON DIFF
(async_def — not gated).

(e) test-stdlib — scripts/run_stdlib.py (the Makefile test-stdlib
rule verbatim: for f in tests/stdlib/test_*.py; do <BIN> $f; done,
each must exit 0, timeout 30s). The tests do
`sys.path.insert(0, "petitpy-lib")` — a path relative to the repo
root — so they MUST run with cwd=the original repo root, exactly as
`make test-stdlib` runs them (running from any other cwd fails every
file with ModuleNotFoundError: No module named 'pytest'). 8 files.
Verified vs the reference first: 8/8.

(f) Corpus nano — scripts/run_nano.py (thin wrapper around
python3 tools/progress.py --config nano --strict <BIN>). INVARIANT
CHECK ONLY: the Rust project has NO nano build; the full binary is
the only binary. Divergences from full-vs-nano config differences
(ROM_LEVEL, frozen set, module tables) are documented in §4, not
fixed here. Calibration: the reference FULL binary scores 454/541
against the nano goldens (fails dominated by int_big* — nano has no
bigints — plus io_bytesio/io_stringio/sys_stdio); the reference NANO
build itself was not built here (it would be 541/541 by construction
of the goldens).

## §3 — Bugs fixed in this lane (with probes)

Fix A — `CallHook` through `type_call` -> `MakeNewFn` (the FunBc
`__init__`/`__new__` stub-seam gap; the D5 4 ignored tests' owner).
A call hook is threaded as a PARAMETER, never stored in `CallCtx`
(storing a closure borrowing `&mut VmState` fails: `Vm::split()`
cannot both return `&mut VmState` and store a closure borrowing it).
`CallHook<'r, 'h> = &'r mut (dyn FnMut(&mut CallCtx, Value, usize,
usize, &[Value]) -> PyResult<Value> + 'h)` (src/objects/slots.rs) —
TWO lifetimes deliberately: `'r` is the reference borrow (shortened
on every reborrow), `'h` the closure's own lifetime; a
single-lifetime alias failed to compile (E0597/E0499). `MakeNewFn =
for<'a, 'r, 'h> fn(&mut CallCtx<'a>, GcRef, &[Value], usize,
Option<CallHook<'r, 'h>>) -> PyResult<Value>`. `type_call` gains the
hook param; `call_type_ctx` (vm_call.rs) builds it from
`call_function_ctx` + the `state.pending_exc` stash (the C14
side-channel idiom); `instance_make_new` uses `with_call_hook_seams`
when hook is Some, else stub seams. Exception types keep the direct
`exception_make_new` path (no `__init__` call — matches the Zig).
Fixed: class2, class_inherit1, class_inherit_mul, class_super,
class_super_object, with_raise, with_return, object_dict,
subclass_native2_list, builtin_dir, builtin_filter, builtin_next_arg2,
async_for2. Probed reference behavior pinned: `__new__` returning a
non-class-type skips `__init__`.
Fix B — hook through `collect_iterable` (`list(map(f, xs))` etc. with
a FunBc `f`): `collect_iterable` gains `mut call:
Option<CallHook<'_, '_>>`, threaded through the CONSTRUCTOR paths
only (list/tuple/dict/set/deque make_new); method paths pass None.
`call_sorted_ctx` also builds the hook, so `sorted(map(f, xs))`
works; the sort KEY function via `call_function_n_kw` (stub) remains
a separate gap (see §4 list_sort). Fixed: builtin_filter (again),
class_inplace_op2 now passes (Rust more conformant than the ref).
Limitation: a `StopIteration` raised by a FunBc through the hook is
NOT classified as exhaustion in collect_iterable's call seam (the
exception object is stashed on `state.pending_exc`, which the
ctx-only fn cannot see).
