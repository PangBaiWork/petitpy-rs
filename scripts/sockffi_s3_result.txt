§4 — FINDINGS (verified by reading code / probing, not assumed)
---------------------------------------------------------------------
1. fromfd must NOT dup and must NOT check SO_TYPE: the integration
   test socket_fromfd_wraps_fd wraps a NON-socket fd
   (os.open('/dev/null', O_RDONLY)) via fromfd(AF_UNIX,
   SOCK_STREAM) and requires fileno() == fd. Only liveness
   validation (fcntl F_GETFD -> EBADF). This pins petitpy's
   behaviour, NOT CPython's (CPython dups).
2. fromfd DOUBLE-OWNERSHIP hazard (same class as H-select §4(9)):
   the wrapped fd stays in state.os_fds too. Closing the socket
   closes the fd; the stale os_fds File then aborts the DEBUG
   build (IO Safety violation) when the VM drops. The lane's lib
   tests use detach() instead of close() to release fromfd
   sockets (fd closed exactly once, by os_fds). The release
   binary is unaffected (double close is benign EBADF there;
   integration gate 202/202 proves it). A real fix (dup on
   fromfd, or removing the fd from os_fds) would break the
   pinned fileno() == fd behaviour — left for the main agent.
3. sendmsg/recvmsg on an UNBOUND socket: the table holds the
   AF_INET placeholder UdpSocket, but the instance may claim
   AF_UNIX — sending a sockaddr_un to it is EAFNOSUPPORT (97).
   msg_fd() resolves the real fd: bound/connected sockets use
   their stored fd; unbound INET datagrams use the placeholder
   (CPython auto-binds UDP); unbound AF_UNIX datagrams swap in
   a real UnixDatagram::unbound() first (same swap_in as
   bind/connect, settings migrate); unbound stream -> EINVAL,
   listener -> ENOTCONN (send) / EINVAL (recv).
4. select on sockets is now LIVE under the feature: poll(2)
   timeout 0, POLLIN|POLLERR|POLLHUP. A listener WITH a pending
   connection reports readable (CPython behaviour); with no
   connection it stays not-ready (h_select_socket_no_data_
   not_ready and the devnull/listener sanity probes still pass
   on both builds).
5. Winsock facts recorded for S1/S2 merge: WSARecvMsg takes 5
   args (flags back in msg.dwFlags), WSASendMsg takes 6 (flags
   is an input); AF_INET6=23, AF_UNIX=29, SOL_SOCKET=0xFFFF,
   SO_TYPE=0x1008, FIONBIO=0x8004667E, INVALID_SOCKET=usize::MAX,
   WSADATA 408 bytes opaque, select nfds ignored (pass 0),
   fd_set = u32 count + 64 SOCKETs.
6. Test flake found + fixed: the two fromfd lib tests shared one
   temp path (keyed only by process id) and ran in parallel —
   one removed the file while the other os.open'd it (ENOENT).
   Paths are now distinct (petitpy_fromfd_sock_ / _f5b_).
   Verified 8/8 clean runs in isolation.
