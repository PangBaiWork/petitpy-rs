§1 — What was built
--------------------
FFI + module work, all under `--features unsafe-ffi`, pure Rust
std otherwise, 0 dependencies, 0 new warnings:

- src/support/ffi.rs (commit ae7ac43): private `mod ffi_b` with
  externs `socket`, `bind`, `listen`, `getsockopt`, `kill`,
  `dup2`; safe wrappers `sys_socket`, `sys_bind`, `sys_listen`,
  `sys_getsockopt` (returns Vec<u8> of the RETURNED buflen),
  `sys_kill`, `sys_dup2`; `#[repr(C)] SockaddrUn { sun_family:
  u16, sun_path: [u8; 108] }` (110 bytes) with
  `new_unix(path, plen)`; consts `AF_UNIX=1`, `SIGTERM=15`,
  `SIGKILL=9`. G6a pattern (errno read immediately after the
  failed call).
- src/modules/modsocket.rs (731bca2): U6 — real `socket(2)` fd
  for every socket (default: `OwnedFd::from(File::open(
  "/dev/null"))` placeholder; feature: `OwnedFd::from_raw_fd`
  of the `socket(2)` fd); `bind()` runs the real `bind(2)`
  (same fd — fileno stable), `listen()` runs the real
  `listen(2)` (bound-not-listening until then; `accept()` on
  it is the kernel's EINVAL 22); `Foreign(Option<OwnedFd>)`
  (default None, feature Some(owned)). U4 — `socket_fromfd`
  wraps the LIVE fd (feature) instead of an anonymous pair:
  the fd is closed when the socket closes (os.close(fd)
  afterwards is EBADF 9), `recv` on it goes to the kernel
  (fromfd listener recv is EINVAL 22; fromfd /dev/null fd
  recv is ENOTSOCK 88); if the fd is already in the socket
  table the existing entry is kept (fd owned exactly once).
  U7 — `getsockopt` runs the real `getsockopt(2)` under the
  feature (level/optname/buflen passed through, unknown
  optname is ENOPROTOOPT 92; `SO_PEERCRED` unconnected is
  12 bytes [0,0,0,0,255x8] — pid 0, uid -1, gid -1).
  No new `SocketState` variant: the feature's `bind()` wraps
  the same fd as `UnixListener::from(owned)`; the entry stays
  `Listener` and the kernel decides.
- src/modules/modsubprocess.rs (62801b4): U5 — the timeout arm
  sends `SIGTERM`, polls `waitpid(WNOHANG)` every 10 ms for
  up to 1.0 s of grace, then `SIGKILL` + blocking `waitpid`
  (feature only; default still SIGKILL immediately).
  Returncode is -signum when signaled. U8 — plain-fd stdin /
  stdout / stderr go through a `pre_exec` `dup2` in the child
  (feature only; default still re-opens `/proc/self/fd/<fd>`):
  same fd number, so file offset and O_APPEND are shared and
  socket fds work; `stderr=STDOUT` with `stdout=fd` dup2's
  the child's stdout onto stderr. `pre_exec` ignores dup2
  errors, matching the Zig's `_ = dup2(...)`; verified
  empirically that pre_exec runs AFTER stdio setup, so a
  `Stdio::null()` placeholder is safely overwritten.
  ALSO FIXED (not feature-gated — a bug fix to the shared
  collection path): the old single-`recv()` in `finish`
  waited for pipe EOF after a timeout kill; a killed child's
  grandchild (`sh -c 'sleep 5'`) holds the pipe open, so the
  timeout path took 5.0 s on the reference's 1.3 s (confirmed
  on the master default binary, no G6b). The drain now
  streams chunks and the timeout path takes what has arrived
  so far (10 ms settle first).
- Tests (b063d5b): modsocket_tests.rs — feature-only

§4 — Leftovers (for the main agent)
------------------------------------
1. `sendall` on a listener is EINVAL on Rust, ENOTCONN 107
   on the reference (probed while working G6b): the
   `is_stream` gate rejects non-stream sockets before the
   syscall. Out of scope — the brief leaves `sendall`
   unchanged. README + module docs note it.
2. A drain thread blocked on read may outlive a timed-out
   spawn (leaked thread per call when a grandchild holds the
   pipe) — a consequence of the chunked-drain fix; the
   reference does not have this shape (it uses a different
   collection path). No test covers it; worth a note in the
   triage doc if the main agent wants it tracked.
3. Default build `bind("")` binds an UNNAMED socket (see
   §3) — the old module-docs claim (ENOENT) was wrong and
   is corrected in this lane. No lib test asserts either
   behaviour on default; the probe is the only coverage.
4. The P14 lane ran in parallel in the same VM; its
   compiles slowed G6b builds (release builds ~1m20s each
   under contention).
5. Nano 541/541 is the original's own gate; Rust has no
   nano build — report-only, not targeted.
