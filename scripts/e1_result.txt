§1 — Mapping (what was built, and the design decisions)
--------------------------------------------------------
(a) `petitpy` CLI — src/main.rs + NEW src/entry/:
  - `main.zig` (423) -> main.rs dispatch (version/help/emit-mpy/
    REPL/-c/script, in the Zig's order) + entry/mod.rs (VERSION
    "0.9.0", io_error_name), entry/base64.rs (std base64, `=` pad),
    entry/systemexit.rs, entry/embed_exec.rs, entry/embed_run_mpy.rs.
  - Printed strings match the original byte-for-byte (`petitpy
    0.9.0`, usage saying `petitpy`) although the binary is petitpy-rs.
(b) `petitpy-vm` — NEW src/bin/petitpy-vm.rs (`main_vm.zig`, 233;
    note: it lives at src/main_vm.zig, NOT src/runtime/ as the
    brief's §(b) header suggested — no functional impact).
  - `VmState.compiler_linked: bool`, default true; the vm binary
    sets it false. Checked in `call_eval_exec_ctx` /
    `call_compile_ctx` (builtinevex.rs), `Vm::eval_exec` +
    `eval_exec_ctx` (vm_eval.rs), and `exec_source_in_module`
    (import_search.rs) — the `.py` import compile path. `.mpy`
    imports are NOT gated. The raise is
    NotImplementedError("compiler not linked in petitpy-vm").
  - Missing .mpy -> stderr `error: <Name>`, exit 1; extra args
    after the .mpy path ignored.
(c) `__main__` + sys wiring — the run seam is
    `Vm::run_main_source(src, source_name, file: Option<&str>)`
    (vm_eval.rs): compile FileInput with the caller's source name
    (NOT "__main__"), `register_main_module` (split out of
    `load_module_from_mpy`, which stays a thin wrapper) +
    `wire_script_file_and_path` (`__main__.__file__` + sys.path[0]
    = dirname(script), BEFORE the body runs) + `run_registered_module`.
    `set_sys_argv` added next to `set_sys_path` (syncs the
    sys_argv_list object in place). `compile_error_value_named`
    (pub(crate)) lets the traceback frame carry the caller's source
    name instead of the hardcoded "<string>".
    Env path (`wire_env_sys_path`, embed_exec.rs): PYTHONPATH
    colon-split, empty entries skipped -> PETITPY_LIB, else
    `$HOME/.petitpy/lib` -> `<exe dir>/../share/petitpy/lib` iff
    that directory exists. Runs for script, -c and REPL alike.
(d) REPL — `run_repl` (embed_exec.rs): banner to stderr, `>>> `
    prompt to stderr BEFORE each read (incl. the final EOF read),
    EOF -> "\n" to stderr, exit 0. Each line SINGLE_INPUT, source
    name "<stdin>", SAME persistent globals. Raises print the
    traceback to stderr, loop continues. NO continuation
    (`mp_repl_continue_with_input` is a stub returning false).
    Line buffer 4096 / accumulator 16384 are the C16 readline
    call parameters.
(e) `__repl_print__` — `repl_print_builtin` (vm_builtins.rs):
    non-None arg -> print repr(arg) + "\n" to stdout, return None.
    Bound in `bind_d1_builtins` (NOT `build_builtins`, whose mk_var
    is defined after the print bind). See §3.1 for the REPL_PRINT
    compiler fix.
(f) Obj::Code + `compile()` backend — NEW
    src/objects/callables/objcode.rs (`code_type_data`,
    `new_code`, `is_code` via the arena header type):
    payload `CodeData { module_fun: GcRef }` (value_data.rs);
    `Obj::Code` variant; `children()` -> [module_fun];
    `heap_bytes()` -> 16. The `code` type is built in
    `build_vm_types` like `reversed` (empty dict + code_type_data),
    in the header-type fix loop and the MRO patch loop; `VmTypes`
    gained a `code: GcRef` field. `compile_to_code`
    (compile_bridge.rs) keeps the FunBc from the
    `register_mpy_code_ctx(..., None)` path and wraps it via
    `new_code`. `code_execute` (builtinevex.rs): patches the FunBc
    context module dict to the caller's globals iff exact fun_bc,
    save/restore globals + locals (`locals == globals` -> None,
    the Zig's `dict_locals = null` branch), calls with 0 args.
    `eval`/`exec` check the code fast path BEFORE the buffer read.
(g) D3 registration — NEW `build_d3_modules` (vm_modules.rs):
    math + socket -> `builtin_modules`, struct ->
    `extensible_modules`; `vm.types.socket = Some(socket_type)`
    after drop(ctx); called in `Vm::new` after `build_d2_modules`.
    D3's module files untouched.
(h) Mapping-only:
  - `mp_type_roms.zig` — ROM singletons already built by
    `build_vm_types`; no missing type on the entry path.
  - `vendor_stubs.zig` — 3 live items, all dead-or-covered under
    full (nano-only help shadow; mp_hal_stdout_tx_strn_cooked =
    C8c/C16; mp_repl_continue_with_input -> false). Nothing ported.
  - `lib.zig` — trivial re-export root; Phase F owns it.
  - `tests.zig` — all 16 blocks have Rust equivalents (see §3.7
    for the 4 gaps found and pinned). Compiler test CLIs
    (lexer_test/qstr_test/compile_test, 863 lines) are differential
    harnesses spawning vendor tools (token_dump / mpy-cross); their
    capabilities are already covered by the Rust check scripts
    (check_lexer_corpus.py, check_qstrrt_table.py,
    check_compile_mpy.py 552/552) + unit tests — NO CLI ported,
    no gap found.
  - Cap compliance splits (same commit): `VmTypes` moved from
    vm.rs to vm_types.rs (re-exported from vm.rs; vm.rs 578 ->
    545); `ObjHeader` moved from value.rs to value_data.rs
    (re-exported from value.rs; value.rs 469 -> 451).

§3 — Bugs / corrections / findings
-----------------------------------
3.1 REPL_PRINT bug CONFIRMED and FIXED (brief §(e) was right).
    The Rust handler used `comp.wk(wk_idx::REPL_PRINT)`, interning
    the literal WK_NAMES[16] string `"<repl_print>"` — a name that
    can never resolve, so a REPL `1+1` would have raised NameError.
    Fixed: the REPL branch in handlers_expr_stmt.rs now resolves
    `__repl_print__` on demand via `comp.qstr_from_strn`, exactly
    like `compReplPrintQstr` (compile.zig:2716-2718). The
    `"<repl_print>"` WK entry itself stays (mirrors the Zig table).
    Regression test `repl_single_input_resolves_repl_print`
    (runtime_glue_tests_b.rs); verified through the built CLI
    (`1+1` prints `2` in the REPL).
3.2 repr(c) decision: the Rust code type is the vendor BASIC shape
    — name `"code"` (a static qstr, generated table line 384),
    flags 0, NO print slot — so `repr(c)` is `<code>` (via
    `obj_print_helper`'s no-slot fallback) and `type(c)` is
    `<class 'code'>`. The reference prints `<>` only because its
    stub type has name qstr 0. An earlier prediction of `<>` was
    falsified by the failing test (`repr(c)` came back `"<code>"`).
    Documented divergence, same root cause as the `type()` abort
    (§3.3). The brief pins only `type(c)` as the code type; repr
    was NOT pinned there.
3.3 `type(compile(...))` divergence (NOT a bug): on the reference
    it ABORTS rc=134 (`mp_mirrors.zig:745 fromPtr` null cast —
    `full_stubs.zig` gives `mp_type_code` as 256 zero bytes). Rust
    implements the vendor shape properly (name `"code"`).
3.4 petitpy-vm missing file: Rust reproduces only the first line
    `error: FileNotFound`; the reference then prints a Zig stack
    trace (std/Io paths + main_vm.zig:220). The trace is
    Zig-runtime noise, not reproduced by design (pinned in
    vm_missing_file).
3.5 `io_error_name` maps errno 2/13/21/20/36/40/22 to
    FileNotFound/PermissionDenied/IsDir/NotDir/NameTooLong/
    SymLinkLoop/InvalidArgument; anything else falls back to
    `e.to_string()` — the fallback is UNPROBED (see §4).
3.6 Test-helper bug (no production code involved): the e2e file's
    `b64_decode` mishandled `=` padding (short final chunk shift
    math), so 4 vm tests failed on first run (vm_run_mpy,
    vm_import_math, vm_traceback_stdout, vm_extra_args_ignored);
    the .mpy files whose base64 has no padding passed, which is
    how the bug was isolated. Fixed in the helper; all 45 pass.
3.7 tests.zig mapping check found 4 genuine missing pins — all
    added (all pass):
    - prelude sig: `[0x26]` -> (5,1,0,2,0,0) and `[0x98,0x10]`
      -> n_state 20 (bc_tests.rs).
    - prelude size: `[0x0B]` -> (5,1) and `[0xC8,0x02]` ->
      (100,0) (bc_tests.rs).
    - varint: 0xFFFFFF -> `[0x87, 0xFF, 0xFF, 0x7F]` row
      (bc_tests.rs; the Zig's exact decode input).
    - djb2 literals (qstr.rs `djb2_matches_vendor_precomputed_
      hashes`): os=28537, urandom=44715, st_mode=8606,
      st_ino=24245, "/"=46474, "\n"=46511, "."=46475, ".."=26309,
      "posix"=56408, ""=5381 (values cross-checked in Python
      against the djb2 formula first; the pre-existing test only
      cross-checked __init__/print/zip against the table).
    - parse_num_base: `("ff", 16, 0, 16)` row
      (parsenum_tests.rs).
    Already covered (no action): smallint grid subsumes both Zig
    tests; unicode_full_ascii_table subsumes both unichar tests;
    the zero-remap guard (3-byte search -> 1); parse_num_base's
    other 3 cases; comptime/runtime djb2 agreement is N/A in Rust

3.8 D3 registration kinds verified against the original + D4's
    probe: math/socket are BUILTIN (`MP_REGISTER_MODULE`;
    `import umath`/`import usocket` fail), struct is EXTENSIBLE
    (`MP_REGISTER_EXTENSIBLE_MODULE`; `import ustruct` resolves).

3.9 Cap compliance: E1 grew vm.rs 567 -> 578 and value.rs 459 ->
