## §3 — Fixes (all probed byte-identical vs the reference)

- **Fix 1 — `int_big_rshift` SIGABRT** (`src/vendor/mpz_ops.rs`,
  `shr_inpl`): the round-up path did `dest.dig.truncate(len)`
  after `mpn::shr`, destroying the spare digit the vendor's
  `mpz_need_dig(dest, lhs->len)` (mpz.c:1101) provides; the
  subsequent `mpn::add(&mut dest.dig, &tmp, &[1])` needs
  `out.len() >= a.len()+1` and its final carry write panicked
  ("index out of bounds: the len is 1 but the index is 1" at
  `src/vendor/mpn.rs:142`). Trigger: `(-0xffffffffffffffff) >>
  32` (shifted value all 1s). Fix: `dest.dig.resize(tmp.len()
  + 1, 0)` before the add. The other two `mpn::shr` call sites
  (pow/pow3 loops, mpz_ops.rs:264/309) operate on full clones —
  safe. `not_inpl`'s add branch already resizes to len+1 first
  — safe. Existing shr unit tests 5/5 pass after the fix.
- **Fix 2 — `int_bytes_intbig`** (`src/objects/primitives/
  objint.rs`, `int_to_bytes`): it called `z.as_bytes(!little,
  true, &mut buf)` with `as_signed=true` unconditionally; the
  vendor `mp_obj_int_to_bytes_impl` (objint_mpz.c:115-119)
  passes `as_signed = self->mpz.neg` — the sign-bit overflow
  check applies ONLY to negative ints. Positive heap ints with
  the top bit set (e.g. `(2**64-1).to_bytes(8, 'little')` =
  `b'\xff'*8`) wrongly raised `OverflowError: buffer too
  small`. Fix: `z.as_bytes(!little, z.is_neg(), &mut buf)`.
  Negative behavior unchanged (`as_signed=true` preserved).
  Probed: `(2**64-1).to_bytes(7)` still `OverflowError`,
  `(-1).to_bytes(1) == b'\xff'` (signed), `(-129).to_bytes(1)`
  still `OverflowError`.
- **Fix 3 — `int_parse`** (`src/objects/primitives/objint.rs`,
  `int_make_new_1`): it used `str_bytes_of` (Qstr/Str/Bytes
  only); the vendor `mpObjIntMakeNewImpl` (objint.zig:151-154)
  tries `mp_get_buffer(arg, MP_BUFFER_READ)` after INT_MAYBE —
  ANY buffer provider. Fix: after the `str_bytes_of` check, try
  E2e's safe `buffer_bytes(ctx, arg)` (handles Array incl.
  memoryview view chains) and parse base 10.
  `int(bytearray(b"123"))` and `int(memoryview(b"123"))` now
  work (`int(b"123")` already did).
- **Fix 4 — `builtin_str_hex`** (`src/runtime/vm_types.rs`):
  only memoryview lacked `hex` — bytes/bytearray already
  worked. Vendor `mp_obj_memoryview_locals_dict`
  (objstr.zig:3615-3616) is just the `hex` entry. Fix: the
  memoryview `empty_dict(ctx)` was replaced with a one-entry
  dict built via `locals_dict_from_entries` with `MethodEntry {
  name: "hex", func: bytes_hex_builtin, min: 1, max: 255,
  kw_func: None }`. `bytes_hex` reads self via `buffer_data` →
  `buffer_bytes`, which covers the memoryview source chain.
  Note (probed): `memoryview(b'').hex()` returns `b''` (bytes),
  not `''` — the existing `bytes_hex` empty rule, already
  vendor-faithful.
- **Fix 5 — `__hash__` / `__int__` hook dispatch** (the
  mechanism; four files + one trait method):
  - Root cause (same for both): the slot
    `instance_unary_op_slot` uses stub seams, which cannot run
    a `FunBc` dunder — so `hash(A())` / `int(A())` raised
    `TypeError` even though `instance_unary_op` already
    implements the full vendor HASH / INT_MAYBE logic (member
    path → `finish_unary` truncation / exact-int passthrough;
    no-`__hash__` path → the identity / `__eq__` rule).
  - NEW `hash_of_hook(ctx, types, key, hook)` (`map.rs`):
    instance key + hook → `instance_unary_op(HASH)` via
    `with_call_hook_seams`; else exactly `hash_of`. Also fixes
    `hash_value_to_usize`'s heap-Int arm: `as_int_checked()
    .unwrap_or(0)` → `z.hash_mpz() as usize` (the vendor's
    truncation, objint_mpz.c:420-428 — a `__hash__` returning
    `(1 << 70) | 1` hashed as 0 instead of 1).
  - `map_lookup_hook` / `compact_lookup` / `compact_rehash`
    thread the hook through the hash computation and the rehash
    replays (`map.rs`); NEW `dict_store_hook` (`objdict.rs`,
    `dict_store` refactored to `dict_store_inner` + hook).
    STORE_MAP + STORE_COMP tag 1 (`vm_dispatch_exec.rs`) now
    store with `Some(&mut make_hook(state))` — `{A(): 1}` and
    dict comprehensions over instance keys work, including
    across growth rehashes (20-key regression test).
  - `hash` builtin intercepted by GcRef identity
    (`VmState.hash_builtin`, registered via `D1Bindings` in
    `vm_builtins_bind.rs` — the captured `mk_var` return value,
    NOT a dict lookup; the `mk_var` call order is unchanged) →
    NEW `call_hash_ctx` (`builtin_vm.rs`) routes through
    `hash_of_hook` (one rule, one place).
  - `unary_op_ctx`'s HASH arm (`vm_rt.rs`) also routes through
    `hash_of_hook` (the public `unary_op` wrapper path).
  - `int_make_new_slot` (`make_new.rs` — see the §4 note):
    with a VM hook, a 1-positional-arg user instance runs
    `instance_unary_op(INT_MAYBE)` first; `Some(v)` is the int
    itself (`finish_unary` passes an exact int through, so
    `1 << 100` survives); `None` falls through to
    `int_make_new` (raises `IntConversion`).
  - NEW `VmHook::take_pending` (`slots.rs`, default `None`;
    `StateHook` takes `state.pending_exc`). See the vendor
    raise rule below — this is how the caller tells a
    member-call raise apart from a bad return, and discards
    the stashed raise instead of leaking it.
  - **Vendor raise rule (probed + read in the original —
    runtime.zig `mpUnaryOpImpl`, objtype.zig
    `instanceUnaryOpImpl` B2, pyerr.zig `bridge`/`raiseMsg`):**
    a slot raise inside `mp_unary_op` is SWALLOWED by the op's
    own "not implemented" TypeError — for HASH the fallthrough
    `raiseMsg(TypeError, "unsupported type for operator")`
    overwrites the pending raise; for INT_MAYBE the NULL return
    makes the caller raise "can't convert to int". A NON-INT
    RETURN raises "can't convert to int" in `finish_unary`
    (`mp_obj_get_int`, C-nlr — it bypasses the fallthrough).
    The `"%d" % x` path is DIFFERENT and propagates (E2e's
    existing behavior, verified byte-identical — untouched).
    Probed on the reference: `hash(R())` → TypeError
    "unsupported type for operator"; `{R(): 1}` → same;
    `int(R())` → TypeError "can't convert to int";
    `hash(D())` (`__hash__` returns None) → TypeError "can't
    convert to int"; `int(BadInt())` → same; `"%d" % R()` →
    ValueError (propagates). All six now match byte-identically
    (messages asserted in the new regression tests, including a
    no-leak check: a `sorted(key=)` after a swallowed raise
    still works).
  - Regression tests: 9 new tests in NEW
    `src/runtime/vm_tests_e2h.rs` (rshift no-panic, to_bytes
    top-bit, int-from-buffer, memoryview hex, hash user class
    incl. truncation + messages, hash-raise swallow + no-leak,
    dict growth rehash, int user class incl. `1 << 100`,
    int-raise → "can't convert to int").
